# 더미데이터 삽입 방법

## 유의사항

기본적으로 서버실행시, 아래 데이터들이 자동적으로 삽입되지만, flyway migration이 동작하지 않아 별도의 sql문이 필요한 경우, 아래 데이터들을 실제로 삽입합니다. 새로운 데이터를 삽입하기 원하는 경우, 아래 형식에 맞추어 sql문을 작성 후 실행합니다.

[DB 스키마](./DB스키마.md)를 먼저 생성한 후 아래 sql문들을 실행합니다. 외래키 때문에 **2(계정) → 3(UMI) → 4(로봇) → 5(스킬) → 7(학습 데이터) → 8(모델 파일) → 6(작업)** 순서로 실행합니다. 작업 단계가 모델 버전을 참조하므로 6번 SQL은 마지막에 실행합니다. 각 SQL 블록은 트랜잭션 단위이며, `ON CONFLICT DO NOTHING`은 기존 행을 덮어쓰지 않습니다. 다른 UUID로 같은 handle_number·skill_key가 이미 존재한다면 먼저 충돌을 확인해야 합니다. 기존 행을 최신 값으로 갱신하거나 전체 데이터를 초기화하는 스크립트는 아닙니다.
Linux에서 `S15P21A103/BE/EC2_`으로 이동 후 각 SQL 블록을 `seed-category.sql`로 저장한 뒤 에서 다음과 같이 실행할 수 있습니다.

```bash
cd S15P21A103/BE/EC2_
nano seed-category.sql

# vim 설치되어 있을 시
vi seed-category.sql

docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1' < seed-category.sql
```

## 2. 개발 계정 삽입

### 2.1. 기존 admin01 계정 삽입

현재 개발용으로 사용중인 계정정보는 다음과 같습니다.
```text
ID : admin01@ssafy.local
PW : 12345678
```

사용자 ID는 이후 UMI·로봇·스킬 등의 `owner_id`가 참조하는 **50000000-0000-4000-8000-000000000001**로 고정합니다. `password_hash`에는 원본 마이그레이션의 BCrypt 해시를 사용하며 평문 비밀번호를 넣지 않습니다.

## 7. 학습 데이터

### 주요 데이터

| 항목 | 값 |
|---|---|
| 테이블 | storage_nodes, retention_policies, episodes, episode_archives |
| 저장 노드 | S3 1건, GPU LOCAL 1건 |
| 보관 정책 | 1건 |
| Episode / 아카이브 | 각각 11건 |
| 수집 장치 | UMI-001 |
| 외래키 선행 데이터 | 사용자, UMI 장치, 스킬 |

| 연결 스킬 | 팔 올리기, 청기잡기, 구운감자 옮기기 |
| 최종 학습 / 모델 상태 | SUCCEEDED / READY |
| 모델 위치 | 각 행의 checkpoint_bucket + checkpoint_key |
| 파일 검증 정보 | checkpoint_sha256, checkpoint_bytes |
| 모델 계약 | camera_names, input_schema, output_schema, action_spec, runtime_spec |

`training_jobs.result_skill_version_id`와 `skill_versions.training_job_id`가 서로 참조하므로 학습 작업은 결과 모델 ID를 NULL로 먼저 넣고, 모델을 삽입한 다음 결과 모델 ID를 연결합니다. 모델의 `gate_passed`는 DB 생성 컬럼이므로 INSERT에 넣지 않습니다. 아래 평가 값은 기존 더미데이터의 재현이며 실제 성능 측정 결과로 사용하지 않습니다.

SQL은 모델 파일 자체를 저장하지 않습니다. 지정된 S3 버킷·키에 실제 파일을 별도로 업로드하고 해시와 바이트 수가 일치해야 다운로드·배포가 가능합니다.다른 파일을 등록할 경우 예제 해시·크기를 그대로 재사용하지 않습니다.

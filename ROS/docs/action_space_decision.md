# 액션 공간 결정 (제안) — 관절각 vs EE pose

> ROS 파트가 올리는 **제안(advocacy)**. 실제 계약(`AI/contract/episode.py`) 변경은 AI 트랙 소유이며,
> 양 트랙(A·B) 합의 + D-AI 기록으로 확정한다. 이 문서는 그 결정을 위한 근거 정리다.
> 승인 필요: 트랙 A(데이터) · 트랙 B(정책) · ROS.

---

## 1. 제안

**EE pose(상대) 로 확정.** 위치 델타 + 6D 회전 + 그리퍼 (dim 10).

## 2. 왜 (근거)

| # | 근거 |
|---|---|
| 1 | **데이터 소스가 pose다.** arpose(ARCore 폰)가 네이티브로 SE(3)(위치+쿼터니언)를 뱉는다. 관절 개념 없음 |
| 2 | 관절각으로 가면 **매 프레임 IK 변환** 필요 → 해 가지(branch) 튐 → 관절 궤적 불연속 → 정책 오염 |
| 3 | **arpose 팀도 이미 "t₀ 기준 상대 SE(3) 궤적"** 을 학습 포맷으로 계획 (`APP/arpose/README.md` 다음 단계) |
| 4 | 45(MoveIt IK)가 EE→관절 변환 담당 → **드라이버는 관절각만, 하드웨어 절연** |
| 5 | 크로스 임베디먼트 — 팔이 바뀌어도 데이터 재사용 |

## 3. 두 선택지 비교

| | 관절각 (현 계약) | **EE pose (제안)** |
|---|---|---|
| arpose 원본과 거리 | 멂 (IK 변환 필요) | **가까움 (거의 그대로)** |
| 데이터 오염 위험 | IK 가지 튐 | 없음 |
| IK 위치 | 데이터 생성 시 | **실행 시 1곳 (IK 노드)** |
| 팔 교체 시 데이터 | 폐기 | **재사용** |

## 4. 제안 스펙 (요약)

- **state**(관측) = 현재 EE pose (절대, 정규화)
- **action** = 다음 스텝 **델타** EE pose
- **회전** = 6D 표현 (오일러·쿼터니언 아님 — 신경망 안정성)
- **그리퍼** = 차원 예약 (dim 10)
- 정규화·검증기·6D 헬퍼 등 **참조 구현 초안은 AI 파트에 별도 전달** (계약 반영은 AI가 `episode.py`에)

## 5. 영향

- **계약 버전업** (`episode.py` 관절각 → EE pose). 기존 수집 데이터 무효.
  → **비용 거의 0: 지금 학습용 데이터가 없다.** 실물 데이터 쌓기 전인 **지금이 바꾸기 가장 싼 타이밍.**
- 파이프라인: arpose → 오프라인 변환(hand-eye + t₀상대 + 6D) → 학습 → ckpt(+메타) → 젯슨(정책 → IK노드45 → 드라이버)
- ROS: `so101_msgs`에 `EECommand`(pose+gripper) / `JointCommand`(관절각) — 108에서 잠정 정의됨

## 6. 미결 / 조건 (결정과 별개로 진행)

| 항목 | 담당 | 비고 |
|---|---|---|
| **그리퍼 신호 캡처** | APP(arpose) | 현재 미지원. 계약엔 차원 예약. **파지 학습은 신호 확보 후** |
| hand-eye `T_cam→tcp` 실측 | 트랙 A | 오프라인 변환에 상수로 적용 |
| ARCore world→로봇 축 remap | 트랙 A | 결정적 (중력축 정렬) |

## 7. 결정 항목 (회의에서 확정)

3. 그리퍼 차원 예약 방식 (초기 상수 → 신호 확보 후 실값)
4. D-AI 기록 위치·서명

# S.S.A.F.Y Frontend

S.S.A.F.Y(Show Simply Arm Follows You)는 UMI로 수집한 동작 데이터로 로봇을 학습하고, 학습 결과를 작업으로 구성해 로봇에 배포·실행하는 웹 플랫폼입니다.

현재 프론트엔드는 **React 19 + TypeScript + Vinext/Vite** 기반이며, 백엔드 API 연결 전에도 전체 사용자 흐름을 확인할 수 있도록 Mock 서비스로 동작합니다.

## 현재 사용자 흐름

```text
로그인
→ 대시보드
→ UMI 연결 상태 확인
→ 학습 생성
→ 동작 선택
→ 데이터 준비 방식 선택
   ├─ 새 데이터 만들기: 온라인 UMI 선택
   └─ 기존 데이터 사용: 학습 가능한 데이터 선택
→ 학습 내용 확인 및 생성
→ 학습 진행·완료 확인
→ 작업 구성·저장
→ 로봇 선택 및 작업 버전 배포
→ 작업 실행·중지
```

## 화면 구성

| 상단 메뉴 | 화면과 기능 |
|---|---|
| 대시보드 | 장치·학습·최근 작업 요약 |
| 데이터 | 로봇에게 보여준 동작 데이터 목록, 상태 필터, 상세 확인 |
| 학습 | 드롭다운에서 `학습 목록`, `학습 생성`으로 이동 |
| 작업 | 드롭다운에서 `작업 목록`, `작업 생성`으로 이동 |
| 장치 관리 | Robot·UMI 목록, 장치 등록, 로봇 상세 및 설정 |

화면 폭이 좁아지면 상단 메뉴는 햄버거 메뉴로 전환됩니다.

### 구현된 기능

- 랜딩 페이지와 로그인 모달
- 로그인 전 보호 메뉴 접근 차단 및 로그인 후 요청 화면 이동
- 탭을 유지하는 동안 Mock 로그인 상태 유지, 명시적 로그아웃
- 대시보드 요약과 상세 화면 이동
- Robot·UMI 목록, 연결 상태, 장치 등록
- Robot 상세 정보 수정과 모델 적용
- 데이터 목록, 동작·상태 필터, 상세 모달
- 데이터 전송·검증 상태 및 검증 실패 사유 표시
- 단계형 학습 생성과 기존 데이터 다중 선택
- 학습 진행률, 현재 단계, 완료 결과 표시
- 학습 목록 필터, 새로고침, 상세, 취소, 재시도
- 작업 목록과 저장된 작업 불러오기
- 블록 기반 작업 구성, 순서 변경, 삭제, 반복 블록
- 실행 전 검증, 작업 저장, Mock 배포, 실행·중지
- 공통 로딩, 빈 데이터, 오류, 재시도, 토스트
- 데스크톱·태블릿·모바일 반응형 UI

## 데이터 상태

백엔드 API 명세의 Episode 상태를 다음과 같이 표시합니다.

| API 상태 | 화면 표시 | 의미 |
|---|---|---|
| `REGISTERED` | 등록 완료 | 파일 업로드 대기 |
| `UPLOADING` | 업로드 중 | 영상·센서 데이터 전송 중 |
| `VALIDATING` | 확인 중 | 파일 형식·무결성 확인 중 |
| `READY` | 학습 가능 | 학습 입력으로 선택 가능 |
| `INVALID` | 확인 실패 | 실패 사유 확인 후 재수집 필요 |

## 핵심 용어

화면에서는 비개발자도 이해하기 쉬운 표현을 우선 사용합니다.

| 도메인 용어 | 의미 | 화면 표현 |
|---|---|---|
| UMI | 사용자가 보여주는 동작을 수집하는 장치 | UMI, 데이터 수집 장치 |
| Episode | UMI 동작 1회와 결과 파일 묶음 | 데이터 |
| Skill | 로봇이 배울 수 있는 공통 동작 | 동작 |
| SkillVersion | 한 번의 학습으로 생성·검증된 모델 버전 | 학습 결과 버전 |
| Task | 여러 동작을 순서대로 조합한 작업 | 작업 |
| TaskVersion | 실행 순서와 동작 버전을 고정한 버전 | 작업 버전 |
| Deployment | 작업 버전을 로봇에 적용하는 과정 | 배포 |
| Execution | 배포된 작업의 실제 실행 기록 | 작업 실행 |

## 프로젝트 구조

```text
FE/
├─ app/
│  ├─ page.tsx          # 현재 화면과 사용자 흐름
│  ├─ globals.css       # 공통 스타일과 반응형 UI
│  └─ layout.tsx        # 앱 레이아웃과 메타데이터
├─ hooks/
│  ├─ useAppStore.tsx   # 앱 공통 상태와 Mock 데이터 연결
│  └─ useTaskDeployment.ts
├─ mocks/               # 장치·데이터·학습·작업 Mock 데이터
├─ services/            # 인증 및 도메인별 Mock 서비스
├─ types/               # 공통 TypeScript 도메인 타입
├─ public/              # 로고와 랜딩 이미지
├─ DESIGN_SPEC.md       # UI 디자인 규칙
└─ TEAM_SETUP.md        # 팀원 개발 환경 설정 안내
```

현재 화면 컴포넌트는 `app/page.tsx`에 모여 있습니다. 기능이 확장되면 페이지와 공통 컴포넌트를 분리할 예정입니다.

## 로컬 실행

### 요구 환경

- Node.js 22.13 이상
- pnpm 권장

```bash
git switch fe
git pull origin fe
cd FE
pnpm install
pnpm dev
```

개발 서버가 실행되면 [http://localhost:3000](http://localhost:3000)에서 확인합니다.

검증 명령:

```bash
pnpm run lint
pnpm run build
```

`package-lock.json`도 존재하지만 팀 개발에서는 `pnpm-lock.yaml`을 기준으로 pnpm을 사용하는 것을 권장합니다.

## Mock 동작 확인

현재 데이터는 `mocks`와 `services`에서 제공하며 실제 API 호출처럼 짧은 지연이 적용됩니다.

- 로그인 예시: `admin01` / 임의의 비밀번호
- 로그인 상태: `sessionStorage`에 저장되어 탭을 닫거나 로그아웃하기 전까지 유지
- 학습 초안과 일부 작업 결과: `localStorage`에 저장
- 통신 오류 확인: URL 뒤에 `?mockError` 추가

```text
http://localhost:3000/?mockError
```

브라우저 저장소의 로그인 상태와 임시 데이터는 Git에 포함되지 않습니다. 다른 팀원이 저장소를 받아 실행하면 초기 Mock 상태로 시작합니다.

## 백엔드 연동 원칙

실제 API가 확정되면 화면을 직접 수정하기보다 `services`의 Mock 구현을 HTTP 요청으로 교체합니다.

- API 기준 경로: `/api/v1`
- 인증: `Authorization: Bearer {accessToken}`
- 생성·완료 요청에는 명세에 따라 `Idempotency-Key` 적용
- 학습·데이터·장치·배포·실행 상태는 SSE 또는 REST 재조회로 동기화
- API 영문 상태값은 화면용 한글로 변환
- 프론트 보호 화면은 UX를 위한 1차 차단이며 실제 권한은 백엔드에서 검증
- 토큰, 장치 secret, signed URL은 브라우저 로그에 남기지 않음

연동 전 FE·BE 담당자가 확정할 항목:

- 개발 API 주소와 CORS 설정
- Swagger/OpenAPI 주소와 구현된 엔드포인트
- access/refresh token 저장 및 만료 정책
- 신규 데이터 수집을 시작하는 주체와 웹·UMI의 역할
- SSE 제공 여부와 이벤트 payload
- 데이터·학습·배포·실행 상태값과 오류 코드

### API 연결 대상

| 프론트 기능 | API 영역 |
|---|---|
| 로그인·사용자 | `AUTH`, `USER` |
| 장치 관리 | `DEVICE`, `ROBOT` |
| 데이터 | `EPISODE` |
| 학습 생성·목록·진행 | `TRAIN` |
| 학습 결과 모델 | `SKILL`, `MODEL` |
| 작업 구성·버전 | `TASK`, `FLOW` |
| 로봇 배포 | `DEPLOY` |
| 작업 실행·중지 | `EXEC` |
| 실시간 상태 | `EVENT` |

GPU, UMI, Jetson 내부 API는 웹 프론트가 직접 호출하지 않습니다.

## 아직 실제 연동되지 않은 부분

- 실제 사용자 인증과 토큰 갱신·만료
- 실제 장치 등록 및 연결 상태 수신
- UMI 데이터 업로드와 파일별 전송률
- 실제 학습 생성, GPU 진행 상태, 결과 모델 조회
- TaskVersion 서버 검증 및 생성
- Robot 배포와 배포 단계별 상태
- 실제 작업 실행·중지 명령
- SSE 실시간 이벤트 구독과 재연결

현재 화면에서 보이는 위 기능들은 사용자 흐름 검증을 위한 Mock입니다.

## Git 작업 규칙

작업은 최신 `fe`에서 Jira 키를 포함한 기능 브랜치를 생성하고, MR 대상은 `fe`로 설정합니다.

```text
feature/fe/S15P21A103-93-learning-create
fix/fe/S15P21A103-000-description
```

커밋과 MR 제목 예시:

```text
feat: 학습 생성 화면 구현 (S15P21A103-93)
fix: 모바일 메뉴 정렬 오류 수정 (S15P21A103-000)
docs: 프론트 README 최신화 (S15P21A103-000)
```

- 기능 단위 작업 완료 후 MR 생성
- 최소 1명 이상 리뷰 후 병합
- 이미 `fe`에 병합된 기능을 다른 Jira 브랜치에서 다시 커밋하지 않음
- 기존 변경사항 정리 요청일 때는 새 기능을 임의로 추가하지 않음

## 배포 설정

프로젝트에는 Vinext/Vite와 Cloudflare Workers 기반 실행 설정이 포함돼 있습니다. 다만 팀 배포 주소, 환경변수, API 주소가 확정되기 전에는 로컬 Mock 실행을 기본으로 합니다. 배포 설정 변경은 프론트 배포 태스크와 연결하고 팀에 먼저 공유합니다.

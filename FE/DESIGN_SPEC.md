# S.S.A.F.Y 로봇팔 학습 플랫폼 UI/UX 명세서

## 1. 문서 목적

이 문서는 S.S.A.F.Y(Show Simply Arm Follows You) 로봇팔 학습 플랫폼의 PC 웹 와이어프레임과 사용자 흐름을 정의한다.

사용자가 로봇이나 코딩을 몰라도 화면만 보고 다음 행동을 이해할 수 있어야 한다. 전문 용어는 필요한 곳에만 사용하고, 짧은 설명과 명확한 상태 표시를 함께 제공한다.

### 핵심 사용자 흐름

```text
랜딩 페이지
→ 로그인
→ 대시보드
→ UMI·로봇 목록
→ 로봇 상세
→ 학습 현황 확인
```

대시보드에서는 등록 장치, 로봇 상태, 진행 중인 학습을 요약한다. 사용자는 상단 내비게이션을 통해 어느 화면에서도 `PLATFORM`, `LEARNING`, `FLEET`, `WORKFLOW`로 이동할 수 있으며, 로고를 누르면 랜딩 페이지로 돌아간다.

## 2. 제품 범위

### 포함

- 아이디·비밀번호 로그인
- 관리자와 일반 사용자 권한 구분
- 서버에 저장된 UMI 수집 데이터 조회 및 선택
- 수집 영상 불러오기 및 재생
- Skill 학습 설정과 진행 상태 확인
- 블록 기반 로봇 작업 구성, 저장, 불러오기 및 실행
- 사용자별 로봇 접근 권한 관리

### 제외

- 자연어 명령 입력 및 VLM 자동 Skill 선택 UI
- UI에서 UMI 장치에 직접 연결하거나 데이터를 수집하는 기능
- UI에서 로봇을 서버에 등록하거나 삭제하는 기능
- 여러 작업 흐름의 동시 실행

## 3. 사용자와 권한

### 일반 사용자

- UMI 수집 데이터 조회 및 영상 재생
- Skill 학습 생성 및 진행 상태 확인
- 자신에게 접근 권한이 부여된 로봇 조회
- 블록 작업 구성, 저장, 불러오기 및 실행

### 관리자

- 일반 사용자 기능 사용
- 사용자별 로봇 접근 권한 설정
- 서버에 등록된 로봇 자체를 추가하거나 삭제하지는 않음

## 4. 정보 구조

```text
로그인
└─ 메인 애플리케이션
   ├─ 학습
   │  ├─ UMI 핸들 선택
   │  ├─ 수집 데이터 선택
   │  ├─ 영상 재생
   │  ├─ 학습 설정
   │  └─ 학습 진행 및 완료
   ├─ 작업
   │  ├─ 로봇 선택
   │  ├─ 작업 불러오기
   │  ├─ 블록 조립
   │  ├─ 작업 저장
   │  └─ 작업 실행
   └─ 로봇 권한 관리 (관리자 전용)
```

## 5. 디자인 방향

### 핵심 원칙

1. 한 화면에는 하나의 주요 행동만 강조한다.
2. 버튼 이름은 `확인`보다 `데이터 조회`, `학습 시작`처럼 결과가 드러나게 작성한다.
3. 아이콘만으로 기능을 전달하지 않고 항상 텍스트 라벨을 함께 사용한다.
4. 처리 중, 완료, 실패, 비활성 상태를 색상과 문구로 동시에 구분한다.
5. 위험한 행동은 주황색이 아닌 빨간색을 사용해 일반 행동과 구분한다.
6. 전문 용어에는 짧은 도움말을 제공한다.

### 시각적 인상

- 밝고 친근한 서비스형 UI
- 넉넉한 여백과 둥근 모서리
- 흰색과 옅은 회색을 기본으로 사용
- 주황색은 선택 상태와 주요 행동에 제한적으로 사용
- 산업용 제어판처럼 어둡거나 복잡한 표현은 피함

## 7. 타이포그래피와 간격

- 기본 글꼴: `Pretendard`, 없을 경우 시스템 sans-serif
- 페이지 제목: 28px / 700
- 섹션 제목: 20px / 700
- 카드 제목: 16px / 600
- 본문과 버튼: 14px / 400~600
- 보조 설명: 12px / 400
- 기본 간격 단위: 4px
- 일반 컴포넌트 간격: 8px, 12px, 16px, 24px, 32px
- 입력창과 버튼 높이: 최소 44px
- 카드 모서리: 12px
- 버튼과 입력창 모서리: 8px

### 왼쪽 내비게이션

- 학습
- 작업
- 로봇 권한 관리: 관리자에게만 표시

현재 메뉴는 주황색 아이콘, 글자, 옅은 주황색 배경으로 표시한다.

## 9. 화면별 명세

### 9.1 로그인

#### 목적

아이디와 비밀번호로 서비스를 시작한다.

#### 구성

- 서비스 로고와 한 줄 소개
- 아이디 입력
- 비밀번호 입력 및 표시 전환
- 로그인 버튼
- 입력 오류 또는 인증 실패 메시지

#### 동작

- 두 입력값이 모두 있을 때 로그인 버튼 활성화
- Enter 키로 로그인 가능
- 오류는 해당 입력창 아래 또는 폼 상단에 구체적으로 표시

### 9.2 학습: 데이터 선택

#### 상단 안내

`UMI로 수집한 데이터를 선택해 새로운 동작을 학습시켜 보세요.`

UI는 UMI에 직접 연결하지 않는다. 모든 데이터는 서버에서 조회한다.

#### UMI 핸들 선택

- 등록된 핸들 드롭다운
- 핸들 번호 직접 입력
- `데이터 조회` 버튼
- 마지막 조회 시각

드롭다운 선택과 직접 입력은 같은 조회 동작으로 연결한다. 직접 입력값이 있으면 해당 값을 우선 사용한다.

#### 데이터 목록

기본 표시 항목:

- 선택 체크박스
- 영상 썸네일
- 수집 일시
- 촬영 시간
- 파일 크기

서버 데이터 구조가 변경될 수 있으므로 목록은 열 추가가 쉬운 표 형태로 구성한다.

#### 영상 재생

- 데이터 행을 더블클릭하면 서버에서 영상을 불러옴
- 불러오는 동안 행과 플레이어에 로딩 상태 표시
- 영상은 모달 또는 오른쪽 상세 패널에서 재생
- 다운로드나 재생 실패 시 재시도 버튼 제공
- 더블클릭 기능은 발견하기 어려우므로 행에 `더블클릭하여 영상 보기` 안내를 함께 표시

#### 다음 단계

- 선택된 데이터 개수 표시
- 하나 이상 선택되면 `학습 설정으로` 버튼 활성화

### 9.3 학습: 설정

#### 구성

- 선택 데이터 요약
- Skill 이름 입력
- 서버에 등록된 로봇 드롭다운
- 선택한 로봇의 상태 표시
- 이전 버튼
- `학습 시작` 버튼

학습 시작 전 설정 내용을 한 화면에서 검토할 수 있어야 한다.

### 9.4 학습: 진행 및 완료

#### 진행 중

- Skill 이름과 대상 로봇
- 전체 진행률과 진행 막대
- 현재 단계
- 예상 남은 시간
- 시간순 로그
- 취소 기능이 서버에서 지원되는 경우에만 취소 버튼 표시

#### 완료

- 완료 아이콘과 명확한 성공 문구
- 생성된 Skill 이름
- 사용 데이터 개수
- 대상 로봇
- 완료 시각
- `새 학습 시작`과 `작업에서 사용하기` 버튼

#### 오류

- 실패한 단계
- 이해하기 쉬운 오류 요약
- 상세 로그 펼치기
- 서버가 허용하는 경우 `다시 시도` 버튼

### 9.5 작업

#### 상단 도구 영역

- 접근 가능한 로봇 드롭다운
- 로봇 상태 배지
- 저장된 작업 불러오기
- 현재 작업 이름
- 저장 버튼
- 실행 버튼
- 중지 버튼

일반 사용자에게는 관리자가 권한을 부여한 로봇만 표시한다.

로봇 상태:

- 온라인
- 오프라인
- 작업 중
- 오류

오프라인 또는 오류 상태에서는 실행 버튼을 비활성화하고 이유를 표시한다.

#### 왼쪽: 블록 보관함

블록을 유형별로 구분하되 한 목록 안에서 찾을 수 있게 한다.

1. 학습된 동작
   - UMI 학습 체크포인트 블록
   - VLM 사전 학습 작업 블록
2. 직접 제어
   - 모터 제어 블록
3. 흐름 제어
   - 반복 블록

각 블록에는 이름, 간단한 설명, 유형 아이콘을 표시한다.

#### 오른쪽: 작업 캔버스

- `작업 시작` 루트 블록은 항상 하나만 존재
- 모든 블록은 시작 블록 아래 한 흐름으로 연결
- 독립된 두 번째 루트 생성 불가
- 동시 실행 미지원
- 블록 드래그로 추가 및 순서 변경
- 선택한 블록은 테두리와 배경으로 강조
- 빈 상태에는 드래그 방법을 설명하는 안내 표시

#### 모터 제어 블록

- 모터 번호 드롭다운
- 각도 입력 또는 슬라이더
- 모터별 최소·최대 각도는 서버에서 받아 적용
- 현재 허용 범위를 입력 영역 옆에 표시
- 범위를 벗어난 값은 입력할 수 없으며 이유를 표시

#### 반복 블록

- 반복 횟수 입력
- 반복할 블록을 내부에 배치
- 반복 횟수는 양의 정수만 허용
- 중첩 반복은 초기 와이어프레임에서 허용하지 않음

#### 실행 상태

- 현재 실행 중인 블록 강조
- 전체 진행 상태 표시
- 실행 중 편집과 로봇 변경 비활성화
- 중지는 빨간색 버튼으로 구분
- 성공, 사용자 중지, 오류 결과를 명확하게 표시

### 9.6 저장된 작업

- 작업 이름으로 저장
- 저장된 작업 목록에서 불러오기
- 목록 항목: 작업 이름, 수정 일시, 사용 로봇
- 기존 작업을 다시 저장할 때 덮어쓰기 확인
- 삭제 기능은 목록의 보조 행동으로 배치하고 확인 절차 제공

### 9.7 로봇 권한 관리

관리자에게만 표시한다.

#### 흐름

```text
사용자 선택
→ 서버에 등록된 로봇 목록 확인
→ 접근 허용 체크 또는 해제
→ 변경 사항 저장
```

#### 구성

- 일반 사용자 검색 및 선택
- 선택한 사용자 정보
- 서버에 등록된 로봇 목록
- 로봇 번호 또는 이름
- 현재 상태
- 접근 허용 체크박스
- 변경 사항 요약
- 저장 버튼

접근 해제는 사용자와 로봇 사이의 권한만 제거한다. 서버의 로봇 정보는 삭제하지 않는다.

## 10. 공통 컴포넌트

- 주요 버튼: 주황색 채움
- 보조 버튼: 흰색 배경과 회색 테두리
- 위험 버튼: 빨간색 채움 또는 빨간색 테두리
- 입력창: 상단 라벨과 필요 시 하단 도움말
- 상태 배지: 아이콘, 상태명, 색상 조합
- 빈 상태: 원인 설명과 다음 행동 버튼
- 로딩: 스켈레톤 또는 진행 표시와 처리 문구
- 토스트: 저장 완료처럼 짧은 결과만 표시
- 모달: 중요한 확인과 영상 재생에만 사용

## 11. 상태와 예외

각 주요 화면은 다음 상태를 포함해야 한다.

- 최초 진입
- 데이터 없음
- 로딩 중
- 정상 표시
- 일부 데이터 누락
- 서버 오류
- 권한 없음
- 네트워크 연결 끊김

오류 문구는 원인만 알리지 않고 사용자가 취할 다음 행동을 함께 안내한다.

## 12. 접근성과 사용성

- 모든 기능은 키보드로 접근 가능
- 포커스 상태를 2px 이상의 명확한 테두리로 표시
- 드래그앤드롭은 키보드 이동 또는 `작업에 추가` 버튼으로도 수행 가능
- 클릭 영역은 최소 44×44px
- 아이콘 버튼에는 화면 표시명 또는 접근 가능한 이름 제공
- 로그와 상태 변화는 텍스트로도 확인 가능
- 애니메이션은 짧게 사용하고 작업 이해를 방해하지 않도록 함

## 13. 와이어프레임 구현 기준

- 첫 구현은 데스크톱 정적 웹으로 제작
- 실제 서버 연결 대신 화면 상태를 보여주는 최소 샘플 데이터 사용
- 브라우저 기본 기능과 HTML/CSS/JavaScript를 우선 사용
- 외부 UI 프레임워크나 드래그앤드롭 라이브러리는 초기 와이어프레임에 추가하지 않음
- 실제 API 구조가 확정되면 데이터 필드와 상태 처리를 연결

## 14. 미확정 항목

- 수집 데이터 목록에 추가될 메타데이터
- 학습 취소와 재시도 API 지원 여부
- 저장된 작업의 버전 관리 필요 여부
- VLM 사전 학습 작업 블록의 상세 설정값
- 서버가 제공하는 사용자, 로봇, 학습 상태 API 형식

미확정 항목은 현재 와이어프레임 제작을 막지 않으며, 실제 서버 연동 단계에서 확정한다.

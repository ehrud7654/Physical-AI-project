# S.S.A.F.Y 로봇팔 학습 플랫폼 UI/UX 명세서

## 1. 문서 목적

이 문서는 현재 구현된 S.S.A.F.Y(Show Simply Arm Follows You) 웹 와이어프레임의 화면 구조와 UI 기준을 정의한다.

코드 기준 파일은 다음과 같다.

- 화면과 상호작용: `app/page.tsx`
- 공통 스타일: `app/globals.css`
- 메타데이터와 루트 레이아웃: `app/layout.tsx`
- 로고와 랜딩 이미지: `public/`

## 2. 현재 구현 범위

현재 결과물은 React 기반 PC 웹 와이어프레임이다. 화면 데이터는 Mock 데이터이며 백엔드 API, 실제 인증, 로봇 제어 서버에는 아직 연결되지 않았다.

- 랜딩 페이지와 로그인 모달
- 운영 대시보드
- UMI·로봇 목록과 로봇 상세
- 학습 현황과 새 학습 생성 흐름
- 블록 기반 작업 편집기
- 사용자별 로봇 접근 권한 화면
- 로봇·학습 상태 배지와 진행률
- 저장·실행·권한 변경 결과 토스트

## 3. 핵심 사용자 흐름

### 운영 현황 확인

```text
랜딩 페이지 → 로그인 → 대시보드 → 로봇 상태 또는 최근 학습 확인
```

### 로봇 확인

```text
FLEET → 로봇 또는 UMI 탭 → 장치 목록 → 로봇 상세
```

### 학습 확인 및 생성

```text
LEARNING → 학습 현황 → 새 학습 시작 → 시연 데이터 선택
→ 학습 설정 → 학습 진행 → 완료 화면
```

### 작업 생성

```text
WORKFLOW → 실행할 로봇 선택 → 작업 블록 구성 → 작업 저장
→ 안전 안내 확인 → 작업 실행·중지
```

### 관리자 권한 설정

```text
관리자 화면 → 사용자 선택 → 접근 가능한 로봇 선택 → 변경 사항 저장
```

## 4. 공통 내비게이션

모든 주요 화면은 동일한 상단바를 사용한다.

- 로고: `S.S.A.F.Y`와 `Show Simply Arm Follows You`를 함께 표시
- 로고 클릭: 랜딩 페이지로 이동
- `CONSOLE`: 대시보드
- `LIBRARY`: 저장된 작업 조회·실행
- `LEARNING`: 학습 현황
- `FLEET`: UMI·로봇 목록
- `WORKFLOW`: 블록 작업 편집기
- `SIGN IN` 또는 `SIGN OUT`: 인증 상태 전환
- `OPEN CONSOLE`: 대시보드 진입

상단바의 높이, 로고 영역, 메뉴 위치, 우측 버튼 너비는 화면이 바뀌어도 고정한다. 선택된 메뉴는 하단 네이비 선으로만 강조하며 파란 배경은 사용하지 않는다.

현재 화면 전환은 URL 라우트가 아니라 React의 `View` 상태로 처리한다.

## 5. 화면별 명세

### 5.1 랜딩 페이지

- 밝은 로봇 연구실과 그리퍼 작업 이미지를 전체 배경으로 사용
- 좌측에 `SHOW · LEARN · OPERATE` 표시
- 헤드라인: `당신이 보여주는 순간, 로봇의 일이 시작합니다`
- 주요 행동: `플랫폼 둘러보기`, `로그인하기`
- 하단 가치: `ONE`, `LIVE`, `SAFE`
- 로그인 선택 시 페이지 이동 없이 중앙 로그인 모달 표시

### 5.2 로그인 모달

- 랜딩 배경 위 중앙 카드로 표시
- 아이디와 비밀번호를 모두 입력하면 로그인 가능
- 바깥 영역 또는 닫기 버튼으로 모달 닫기
- 현재는 실제 서버 인증 없이 화면 진입만 처리

### 5.3 대시보드

- 등록 UMI 수, 로봇 수, 진행 중 학습, 오늘 완료 작업 요약
- 로봇 상태 목록에서 로봇 상세로 이동
- 최근 학습 목록에서 학습 현황으로 이동
- `새 학습 시작`으로 학습 생성 흐름 진입

### 5.4 UMI·로봇 목록

- 로봇과 UMI를 탭으로 구분
- 장치명, ID, 위치, 연결 상태, 현재 모델과 최근 작업 표시
- 로봇 카드 선택 시 해당 로봇 상세로 이동
- 장치 등록 버튼은 현재 시각 요소만 구현

### 5.5 로봇 상세

- 로봇명, ID, 위치, 통신 상태 표시
- 현재 모델, 오늘 작업, 가동 시간, 오류 알림 요약
- 최근 작업 성공·실패 이력과 배포된 모델 목록
- 온라인 로봇만 `작업 만들기` 활성화

### 5.6 학습 현황

- 전체, 진행 중, 완료, 확인 필요 건수 요약
- 학습명, 로봇, 시작 시각, 현재 단계, 진행률, 상태 표시
- 상태 필터와 새 학습 시작 버튼 제공

### 5.7 새 학습

- 시연 데이터 선택
- Skill 이름과 대상 로봇 설정
- 학습 진행률과 현재 단계 표시
- 진행 완료 시 학습 현황에 완료 항목으로 추가
- 완료된 Skill을 블록 작업의 학습된 Skill 목록에 즉시 반영
- 진행 완료 후 다음 작업으로 이동
- 실제 영상과 학습 서버 대신 샘플 데이터와 타이머 사용

### 5.8 블록 작업

- 학습된 동작, 직접 제어, 흐름 제어 블록 제공
- 클릭 또는 드래그앤드롭으로 작업 흐름에 추가
- 블록 순서 변경과 삭제
- 모터 번호·각도, 반복 횟수와 내부 블록 설정
- 작업 저장·불러오기, 로봇 선택, 실행·중지 상태 표시
- 실행 전 로봇 상태와 작업 유효성 검증 결과 표시

### 5.9 작업 라이브러리

- 저장된 작업의 작업명, 포함 블록, 예상 실행 시간, 최근 수정일 표시
- 작업명과 포함 블록 검색, Skill·제어 블록 포함 여부 필터 제공
- Skill은 학습된 단일 동작, 작업은 여러 Skill·제어 블록을 조합한 실행 흐름으로 구분
- 작업 상세 흐름과 실행할 로봇 선택 제공
- Mock 데이터를 기준으로 로봇 상태와 작업 구성을 실행 전에 확인
- `작업 실행`은 와이어프레임 타이머로 진행·완료 상태 표시
- `수정하기` 선택 시 해당 작업을 블록 작업 편집기로 전달

### 5.10 관리자 권한

- 사용자 검색 및 선택
- 서버 등록 로봇 목록 확인
- 사용자별 접근 허용 체크
- 저장 결과를 토스트로 표시
- 권한 해제는 로봇 자체를 삭제하지 않음

## 6. 디자인 시스템

### 색상

| 용도 | 값 |
|---|---|
| Primary Blue | `#315EFB` |
| Primary Dark | `#2045C7` |
| Primary Soft | `#EEF3FF` |
| Ink / Navy | `#101828` |
| Muted Text | `#667085` |
| Border | `#E5EAF1` |
| Surface | `#FFFFFF` |
| Canvas | `#F5F7FB` |

성공은 녹색, 실패·오류는 빨간색, 진행 중은 파란색, 오프라인은 회색으로 구분한다. 색상만 사용하지 않고 상태명과 점 아이콘을 함께 표시한다.

### 시각 방향

- 밝은 화이트·네이비 기반의 산업용 SaaS 인터페이스
- 과도한 그라데이션과 장식 배제
- 카드 테두리와 약한 그림자로 영역 구분
- 작은 둥근 모서리와 충분한 여백 사용
- 랜딩과 운영 화면에서 동일한 로고와 상단바 유지

### 공통 UI

- 주요 버튼: 네이비 또는 Primary Blue 채움
- 보조 버튼: 흰색 배경과 회색 테두리
- 카드: 흰색 배경, 옅은 테두리, 12px 안팎 모서리
- 상태 배지: 상태별 배경색, 점 아이콘, 텍스트
- 진행률: 막대와 숫자 백분율 함께 표시
- 탭: 선택 항목 하단 선 표시
- 토스트: 저장·변경 결과를 우측 하단에 잠시 표시
- 모달: 로그인과 영상 확인 등 집중이 필요한 작업에 사용

## 7. 반응형 기준

- 기준 화면은 데스크톱 웹
- 넓은 화면에서는 3~4열 카드와 2열 대시보드 사용
- 1100px 이하에서 카드 열 수 축소
- 모바일에서는 상단 메뉴 일부를 숨기고 주요 행동 중심으로 표시
- 현재 발표와 검토는 데스크톱 화면을 우선

## 8. 접근성과 사용성

- 아이콘 버튼에 접근 가능한 이름 제공
- 상태를 색상과 텍스트로 함께 전달
- 버튼 비활성 사유를 화면에 표시
- 드래그앤드롭 블록은 클릭으로도 추가 가능
- 위험 작업 전 안전 확인 안내 표시
- 입력 요소는 라벨과 함께 제공

## 9. 현재 제약과 후속 작업

- 화면 데이터는 `page.tsx` 내부 Mock 배열 사용
- 새로고침 시 현재 화면과 작업 상태 초기화
- 로그인 토큰과 사용자 권한은 실제 인증과 미연결
- 장치 등록, 모델 적용, 상태 필터 일부는 시각 요소만 구현
- 로봇·학습 진행률은 WebSocket 또는 polling 연결 필요
- API 확정 후 `api`, `types`, `mocks` 영역으로 분리 필요
- `page.tsx` 화면 컴포넌트를 기능별 파일로 분리 필요
- 현재 `<img>` 요소는 추후 이미지 최적화 컴포넌트 적용 검토

## 10. 완료 판단 기준

- 랜딩, 로그인, 대시보드, FLEET, 로봇 상세, 학습 현황, WORKFLOW 화면을 확인할 수 있다.
- 상단바 크기와 메뉴 위치가 화면 전환 시 변하지 않는다.
- 로고를 누르면 랜딩 페이지로 돌아간다.
- 로봇과 학습 상태가 텍스트와 색상으로 함께 구분된다.
- `pnpm install`, `pnpm run dev` 후 `http://localhost:3000`에서 실행된다.
- 백엔드 연동 전까지 모든 데이터가 Mock임을 명확히 구분한다.

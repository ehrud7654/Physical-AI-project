# S.S.A.F.Y 프론트엔드 UI/UX 명세

## 1. 목적과 기준

이 문서는 현재 구현된 화면의 정보 구조, 상호작용과 시각 규칙을 정의합니다. 구현 기준은 `app/page.tsx`, `app/globals.css`, `app/layout.tsx`, `public/`입니다.

현재 결과물은 데스크톱·태블릿·모바일에 대응하는 React 웹 프로토타입이며, 데이터와 상태 변경은 Mock 서비스로 제공합니다.

## 2. 정보 구조와 주요 흐름

```text
랜딩·인증
└─ 대시보드
   ├─ 데이터
   ├─ 학습
   │  ├─ 학습 목록
   │  └─ 학습 생성
   ├─ 작업
   │  ├─ 작업 목록
   │  └─ 작업 생성
   └─ 장치 관리
      ├─ UMI
      ├─ 로봇
      └─ 로봇 상세
```

- 학습: 동작 선택 → 새/기존 데이터 선택 → 내용 확인 → 학습 진행 → 결과 확인
- 작업: 목록 검색 또는 새 작업 생성 → 블록 구성 → 저장 → 로봇 선택 → 배포·실행
- 장치: UMI/로봇 탭 → 최근 사용순 확인 → 등록 또는 상세·설정

## 3. 내비게이션

### 데스크톱

- 왼쪽의 떠 있는 남색 사이드바를 사용합니다.
- 로고를 누르면 랜딩으로 이동합니다.
- 메뉴는 `대시 보드`, `데이터`, `학습`, `작업`, `장치 관리` 순서입니다.
- 학습·작업 하위 메뉴는 커서를 올리면 펼쳐지고 영역을 벗어나면 닫힙니다.
- 현재 화면은 배경과 텍스트 대비로 표시합니다.

### 모바일

- 900px 이하에서는 햄버거 버튼과 오버레이 메뉴를 사용합니다.
- 하위 메뉴는 탭으로 열고 닫습니다.
- 메뉴 높이는 항목과 로그아웃 버튼에 필요한 만큼만 사용합니다.

현재 화면 전환은 URL 라우트가 아니라 React의 `View` 상태로 처리합니다.

## 4. 화면별 명세

### 랜딩·인증

- 랜딩은 반사되는 실버 S.S.A.F.Y 로고와 `Smart Solutions All For You` 문구를 중심으로 구성합니다.
- 로그인과 회원가입은 중앙 모달이며 같은 크기·간격·닫기 버튼 규칙을 사용합니다.
- 인증 모달의 로고는 카드 중심에 정렬하고 제목을 중복 표시하지 않습니다.
- 비밀번호 표시 전환, 오류 문구, 포커스 순환과 Escape 닫기를 제공합니다.

### 대시보드

- UMI·로봇·학습·최근 작업을 요약합니다.
- 장치 카드는 해당 UMI/로봇 탭 또는 로봇 상세로 연결합니다.
- 주요 정보 카드의 높이와 내부 정렬을 통일합니다.

### 데이터

- 제목/목록 제어/표를 분리해 하나의 큰 카드처럼 보이지 않게 합니다.
- 우측 상단에 작은 상태 필터와 정렬 드롭다운을 나란히 배치합니다.
- 상태는 전체·학습 가능·처리 중·확인 실패, 정렬은 최신·오래된 등록순과 보관 만료 임박순만 제공합니다.
- 데이터명을 누르면 상세 모달이 열리며 학습 상세 모달과 동일한 헤더·본문·하단 행동 구조를 사용합니다.

### 학습 목록

- 전체·진행 중·완료·확인 필요 건수를 큰 상태 영역에서 한눈에 비교합니다.
- 선택 상태의 불필요한 좌측 강조선은 사용하지 않습니다.
- 목록 제어는 우측에 `마지막 갱신`, `새로고침`, 상태 드롭다운 순으로 묶습니다.
- 진행률, 백분율, 상태 배지는 고정 열에 맞춰 카드 밖으로 넘치지 않게 정렬합니다.
- 학습명을 누르면 상세가 열립니다. 별도의 점 세 개 메뉴는 두지 않습니다.
- 재시도·학습 취소·작업 생성은 상세 안에서 현재 상태에 맞게 제공합니다.

### 학습 생성

- 1 동작 선택, 2 데이터 방식, 3 데이터 선택/수집, 4 내용 확인, 5 진행, 6 결과 순서입니다.
- 완료는 저채도 녹색, 현재 단계는 저채도 파란색으로 구분합니다.
- 데이터 개수의 최소 요구 조건은 실제 정책/API가 확정될 때까지 강제하지 않습니다.
- 설명 문구는 선택과 판단에 필요한 내용만 남깁니다.

### 작업 목록

- 검색은 작업명과 포함 블록을 대상으로 합니다.
- 학습 동작/제어 블록 포함 여부 필터는 제공하지 않습니다.
- `전체 N개`는 목록 헤더 우측에 표시합니다.
- 첫 항목을 기본 선택하지 않으며, 커서를 올린 행만 배경색으로 강조합니다.
- 행을 누르면 상세를 열고 상세에서 편집기로 이동합니다.

### 작업 생성

- 학습 동작, 직접 제어, 흐름 제어 블록을 제공합니다.
- 클릭 또는 드래그앤드롭으로 추가하고 순서 변경·삭제를 지원합니다.
- 모터 각도 범위, 반복 횟수와 내부 블록을 검증합니다.
- 저장 후 로봇을 선택하고 Mock 배포·실행·중지를 확인할 수 있습니다.

### 장치 관리·로봇 상세

- UMI와 로봇을 탭으로 구분합니다.
- 기본 정렬은 최근 사용순이며 오래된 순만 추가 제공합니다.
- `새 장치 등록`은 제목 영역 우측의 공통 생성 버튼 위치에 둡니다.
- 로봇 상세는 현재 모델·오늘 작업·가동 시간·오류, 최근 작업 기록, 설정과 작업 생성 진입을 제공합니다.
- 내부 AI 모델 설치·교체 정보는 일반 사용자의 작업 흐름과 직접 관련이 없어 상세 화면에서 숨깁니다.

### 관리자

- 사용자 선택, 접근 가능한 로봇 체크, 권한 저장을 제공합니다.
- 권한 해제는 장치 삭제가 아님을 안내합니다.

### 시각 방향

- 남색을 구조와 행동의 기준색으로, 실버는 로고와 미세한 반사 표현에 사용합니다.
- 페이지 배경은 끊긴 경계가 보이지 않는 연속적인 밝은 그라데이션을 사용합니다.
- 강한 원색과 전형적인 다색 AI 그라데이션은 피합니다.
- 카드의 테두리와 그림자는 얇고 부드럽게 사용합니다.
- SUIT Variable 글꼴과 넉넉한 행간으로 한글 가독성을 유지합니다.

### 공통 컴포넌트

- 생성 행동: `새 학습 생성`, `새 작업 생성`, `새 장치 등록`; 얇은 테두리와 우측 chevron을 가진 작은 버튼
- chevron: 텍스트의 시각적 세로 중심에 정렬
- 드롭다운·새로고침: 페이지 전반에 같은 낮은 높이와 테두리 사용
- 상태 배지: 점·텍스트·저채도 배경을 함께 사용
- 진행률: 막대, 숫자, 배지를 고정된 그리드에 배치
- 상세 모달: 제목/닫기, 정보 본문, 조건부 행동 영역의 동일한 구조
- 토스트: 결과를 우측 하단에 짧게 표시

## 6. 반응형

- 기본은 데스크톱이며 카드와 표는 가용 폭 안에서 정렬합니다.
- 1100px 이하에서 다열 카드 수와 간격을 줄입니다.
- 900px 이하에서 사이드바를 모바일 메뉴로 바꿉니다.
- 680px·560px 구간에서는 제어 버튼을 줄바꿈하고 표를 카드형 정보로 재배치합니다.
- 긴 텍스트, 진행률, 상태 배지는 수평 스크롤이나 화면 밖 넘침 없이 표시해야 합니다.

## 7. 접근성과 사용성

- 입력은 보이는 라벨과 함께 제공합니다.
- 아이콘 버튼에는 `aria-label`을 제공합니다.
- 상태는 색상만이 아니라 텍스트와 점으로 전달합니다.
- 모달은 `role="dialog"`, `aria-modal`, Escape 닫기와 포커스 순환을 사용합니다.
- 드래그 가능한 블록은 클릭으로도 추가할 수 있습니다.
- 비활성·실패 상태에는 사용자가 취할 수 있는 다음 행동을 표시합니다.

## 8. 구현 제약과 후속 작업

- 실제 인증·장치·학습·배포·실행 API는 아직 연결되지 않았습니다.
- Mock 데이터와 서비스는 `mocks`, `services`, 공통 상태는 `hooks/useAppStore.tsx`에 분리돼 있습니다.
- 로그인 상태는 `sessionStorage`, 학습 초안과 일부 결과는 `localStorage`를 사용합니다.
- 화면 컴포넌트가 큰 `app/page.tsx`에 모여 있어 기능별 분리가 필요합니다.
- `View` 상태 전환은 추후 실제 라우팅과 딥링크로 교체할 수 있습니다.
- 이미지 최적화와 실시간 상태 갱신 방식은 API·배포 환경 확정 후 결정합니다.

## 9. 완료 기준

- 랜딩, 인증, 대시보드, 데이터, 학습, 작업, 장치와 관리자 화면을 확인할 수 있습니다.
- 데스크톱/모바일 내비게이션이 각 입력 방식에 맞게 동작합니다.
- 목록 제어와 생성 버튼의 크기·위치가 화면 간 일관됩니다.
- 행과 상태는 기본 선택처럼 보이지 않고 사용자 상호작용에만 반응합니다.
- 카드·표·진행 상태가 화면 밖으로 넘치지 않습니다.
- `pnpm lint`와 `pnpm build`가 통과합니다.
- 실제 연동 전 기능은 Mock임을 문서와 코드에서 구분합니다.

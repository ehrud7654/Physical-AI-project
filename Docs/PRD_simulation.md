## 1. 제품 개요

**사람이 UMI 장치로 수집한 작업 시연을 로봇 학습에 활용하고, 사용자가 웹에서 데이터 전송·학습·시뮬레이션 평가·모델 배포 상태를 확인할 수 있는 플랫폼을 만든다.**

플랫폼은 회원 및 UMI 핸들별로 데이터를 구분하고, GPU 서버의 학습 결과를 버전으로 관리한다. 시뮬레이션 워커는 학습 결과를 고정된 가상 환경에서 평가하고 지표·재생 자료를 기록한다. Jetson Orin Nano는 평가 결과를 검토해 승인된 모델을 받아 로봇팔 실행 환경에 적용한다. 후속 단계에서는 시뮬레이션에서 생성한 학습 데이터를 활용한 모델을 실제 로봇에서 비교 평가한다. 장기적으로는 Scratch형 블록 UI를 통해 학습된 작업을 조합하고 실행하도록 지원한다.

### 제품이 해결하려는 문제

다음은 검증이 필요한 문제 가설이다.

| 문제 가설 | 사용자에게 발생하는 불편 | 제공할 가치 |
|---|---|---|
| 데이터 수집·학습·로봇 적용 과정이 분리되어 있다 | 각 장비와 서버에서 상태를 따로 확인해야 한다 | 웹에서 전체 과정과 실패 지점을 확인 |
| 영상 이름만으로 시연을 관리하면 장치·학습 실행과 연결하기 어렵다 | 어떤 데이터가 어떤 모델에 사용되었는지 추적하기 어렵다 | 시연 → 학습 → 모델 → 배포 이력 연결 |
| 파일 전송 완료와 학습 완료가 혼동된다 | 실제 준비 상태를 잘못 판단할 수 있다 | 단계별 상태와 집계 기준을 명시 |
| 체크포인트 적용이 수동으로 이루어진다 | 잘못된 버전 적용이나 배포 실패를 파악하기 어렵다 | 고정 버전 선택·검증·적용 결과 확인 |
| 로봇 작업 조합에 개발 지식이 필요하다 | 비개발자가 작업을 구성하기 어렵다 | 검증 가능한 블록형 작업 구성 제공 |

## 2. 목표와 비목표

### 목표

| ID | 목표 | 확인 방법 |
|---|---|---|
| G-01 | 사용자가 자신의 UMI·시연·학습 결과를 구분해 관리 | 계정별 리소스 분리 및 권한 테스트 |
| G-02 | 시연 수집부터 모델 적용까지 상태를 추적 | 대표 시나리오에서 단계별 상태·실패 사유 확인 |
| G-03 | 학습 결과의 입력 데이터·설정·버전을 추적 | 배포된 모델에서 원본 학습과 입력 목록까지 조회 |
| G-04 | 실패·재접속·중복 요청에도 상태 일관성 유지 | 장애 및 재요청 시나리오 테스트 |
| G-05 | 승인된 모델로 제한된 로봇 작업을 수행 | 합의한 작업·환경에서 실물 검증 통과 |
| G-07 | 학습 결과를 실물 적용 전에 시뮬레이션에서 테스트 | 고정 모델·환경으로 평가 실행 및 결과 조회 |
| G-08 | sim-to-real 학습의 효과를 실측 | 실제 UMI 데이터만 사용한 기준 모델과 실제 작업 성과 비교 |
| G-06 | 블록으로 작업을 구성하는 사용자 경험 제공 | 확장 범위에서 저장·검증·실행·중지 시나리오 확인 |

### 비목표

- 모든 종류의 로봇팔·작업·환경을 지원하는 범용 로봇 플랫폼.
- 웹이나 EC2에서 모터의 실시간 제어 주기를 직접 수행하는 기능.
- 새 학습 알고리즘 자체의 연구 성과 또는 학습 성공률 보장.
- 검증 없이 최신 모델을 자동 설치하거나 로봇 동작을 자동 시작하는 기능.
- MVP에서의 복잡한 블록 분기·반복·임의 코드 실행.
- 결제, 공개 모델 마켓, 조직별 협업 권한, 일반적인 로봇 관리 제품의 모든 기능.

| 환경·평가 데이터 저장 계층 (추가) | 원본 그림에 없는 신규 논리 구성 | 환경·로봇 자산 버전, 실행 설정, 지표·영상 보관 |
| Robot Arm | 모터 제어 및 작업 수행 | 정의된 환경에서 안전하게 작업 수행 |

### 확정되지 않은 부분

1. **파일 저장 위치:** 그림은 DB에 메타데이터와 버전을 표시하지만 실제 영상·IMU·체크포인트 저장소는 명시하지 않는다. DB는 메타데이터를, 파일 저장 계층은 대용량 파일을 담당하는 방식을 제안한다.
2. **파일 전달 경로:** EC2 경유 전송인지 파일 저장소를 통한 전달인지 확정이 필요하다. 사용자는 실제 전송·검증 결과를 확인할 수 있어야 한다.
3. **영상 1개씩 전송:** 이는 파일 전송 순서·동시성 제약으로 해석한다. 영상 하나가 학습 작업 하나라는 의미로 고정하지 않는다.
4. **VLM과 제어:** 그림의 VLM 활용은 기술 방향이다. 사용할 모델, 입력·출력, 정책 모델과의 관계, Jetson 실행 가능 여부는 검증 전이다. VLM 출력이 곧바로 안전한 모터 명령이라고 가정하지 않는다.
5. **ROS 2:** 대화의 학습 주제이지만 첨부 그림에서 확정한 구성 요소는 아니다. 도입 여부와 노드 설계는 기술 검증 후 결정한다.
6. **GPU 할당·Jetson 통신:** claim, heartbeat, SSE는 앞선 API 초안의 구현 제안이다. 제품 요구는 상태 관측·신뢰성 확보이며 프로토콜 자체를 확정하지 않는다.

### 시뮬레이션 통합 흐름

```text
UMI → 시연 업로드·검증 → GPU 학습 → 모델 버전
                                      ↓
EC2 평가 요청 → 시뮬레이션 워커 → 지표·영상·로그 → 웹 평가 결과
                                      ↓
                           평가 기준 통과 및 운영자 승인
                                      ↓
                           Jetson 적용 → 실제 로봇 검증

후속: 가상 환경·데이터 생성 → 시뮬레이션 기반 학습/보완 → 새 모델 버전
      → 독립 시뮬레이션 평가 → 승인 → 실제 평가 → 차이 분석·다음 학습
```

EC2는 평가 작업과 권한·상태를 관리하고, 시뮬레이션 계산은 워커가 담당한다. 워커를 기존 GPU 서버와 공유할지 분리할지는 자원 실험 후 결정한다. 공유 시 학습·평가 간 자원 제한과 대기 상태를 관리한다. 워커의 가상 제어 명령이 실제 로봇으로 전달되지 않도록 실행 경로·자격 증명을 분리한다.

## 5. 핵심 사용자 여정

| 단계 | 사용자 또는 시스템 행동 | 사용자가 확인할 결과 |
|---|---|---|
| 1. 로그인 | 계정으로 접속 | 자신 소유의 UMI·로봇 목록 |
| 2. UMI 연결 | 핸들 정보와 소유 확인 수단으로 등록 | 연결된 장치와 기본 정보 |
| 3. 시연 수집 | UMI로 대상 작업 시연 | 등록된 시연 식별자·작업명 |
| 4. 전송·검증 | 영상·IMU·메타데이터 전송 후 검증 | 준비 완료 또는 실패 사유 |
| 5. 학습 요청 | 준비된 시연과 학습 설정 선택 | 고유 학습 실행 및 대기 상태 |
| 6. 학습 관제 | GPU가 데이터를 수신하고 학습 | 현재 단계·진행도·실패 원인 |
| 7. 모델 확인 | 산출물을 등록·검증 | 입력 학습과 연결된 모델 버전 |
| 8. 시뮬레이션 요청 | 모델·환경 버전·테스트 시나리오 선택 | 고유 평가 실행과 대기 상태 |
| 9. 결과 검토 | 지표·영상·실패 이유 확인 | 완료 여부와 기준 통과 여부를 별도로 확인 |
| 10. 배포 | 대상 로봇과 호환 버전 선택 | 다운로드·검증·적용 성공 또는 실패 |
| 11. 실물 확인 | 로컬 안전 절차에 따라 제한된 작업 실행 | 실제 로봇 작업 결과 |
| 12. 블록 실행 | 확장 범위에서 작업 조합·검증·실행 | 실행 노드·결과·중지 확인 |

### 실패 시 기대 경험

| 상황 | 사용자에게 보여줄 정보 | 복구 원칙 |
|---|---|---|
| 업로드 중 네트워크 단절 | 미완료 파일과 현재 상태 | 재전송해도 동일 시연 중복 등록 방지 |
| 파일 검증 실패 | 파일별 원인 및 재전송 가능 여부 | 학습 대상으로 선택되지 않도록 차단 |
| GPU 미할당·지연 | 대기 상태와 마지막 갱신 시각 | 대기를 오류나 진행률 0의 실행 상태와 구분 |
| GPU 중단 | 현재 학습의 복구·실패 상태 | 이전 워커의 늦은 보고가 상태를 덮어쓰지 않음 |
| 시뮬레이션 실행 오류 | 환경 로드·모델 인터페이스 오류 및 마지막 상태 | 오류를 정책 실패나 성공으로 집계하지 않고 재실행 이력 보존 |
| 평가 기준 미달 | 실패 시나리오·지표·영상 | 모델을 보존하되 배포 승인을 차단하고 재학습 검토 |
| 배포 실패 | 대상 버전·실패 단계·원인 | 기존 정상 모델 유지, 실패를 성공으로 표시하지 않음 |
| 로봇 연결 단절 | 마지막 확인 상태와 연결 끊김 | 실제 정지 여부를 추정하지 않음 |
| 새로고침·재로그인 | 서버에 저장된 현재 상태 | 실시간 이벤트 수신 이력 없이도 조회로 복구 |

### 상태 모델

| 대상 | 정상 흐름 | 실패·취소 원칙 |
|---|---|---|
| Episode | 등록 → 업로드 → 검증 → 준비 완료 | 검증 실패는 학습 불가. 수정된 파일 기술 정보는 새 데이터로 구분 |
| Training Job | 대기 → 입력 준비 → 학습 → 성공 | 실패·취소 별도. 재시도 이력 보존 |
| Model Version | 검증 중 → 사용 가능 | 실패한 산출물 사용 차단. 학습 체크포인트와 배포용 파일 구분 |
| Deployment | 대기 → 다운로드 → 검증 → 적용 → 성공 | 실패 시 기존 정상 모델 유지 |
| Simulation Run | 대기 → 환경 준비 → 실행 → 결과 집계 → 완료 | 실행 오류·취소는 별도 종료. 완료와 평가 통과는 별도 필드 |
| Evaluation Verdict | 미평가 → PASS / FAIL / INCONCLUSIVE | 기준 미확정·필수 시행 누락·관측 불충분은 INCONCLUSIVE |
| Execution | 대기 → 실행 → 성공 | 중지 요청과 실제 중지 구분. 연결 단절만으로 종료 판정 금지 |

### 진행도 집계 규칙

| 표시 항목 | 정의 |
|---|---|
| 등록된 시연 수 | 해당 UMI의 고유 episode 수 |
| 업로드 완료 수 | 전체 필수 파일이 업로드된 것으로 서버가 확인한 고유 episode 수 |
| 학습 가능 수 | 데이터 검증을 통과한 고유 episode 수 |
| GPU 수신 수 | 선택한 학습 실행에서 수신·검증한 고유 episode 수 |
| 학습 대상 수 | 선택한 학습 실행에 고정된 episode 수 |
| 성공 학습 포함 시연 수 | 성공한 학습 실행에 한 번 이상 포함된 고유 episode 수 |
| 학습 진행률 | 해당 실행의 현재 단계와 학습 진행 기준에 따른 비율 |

그림의 “학습 완료 영상 수”는 영상 하나씩 학습이 완료된다는 오해를 줄이기 위해 “성공 학습 포함 시연 수”로 표현한다. 데이터가 여러 학습에 쓰여도 UMI 전체 집계에서는 중복 계산하지 않는다. GPU 수신 수는 학습별 범위를 명시한다.

## 9. 비기능 요구사항

수치가 있는 항목은 개발 전 합의할 제안 목표이며 실측 결과가 아니다.

| 영역 | 요구사항 | 검증 기준 |
|---|---|---|
| 보안 | 사용자·UMI·GPU·Jetson 인증·권한 분리 | 역할 교차 호출 및 타 계정 접근 테스트 통과 |
| 파일 보호 | 비공개 저장 및 제한된 파일 접근 | 무권한 다운로드·검증 후 덮어쓰기 차단 |
| 중복 처리 | 재요청·큐·장치 명령 중복 수신 안전성 | 같은 작업·모델·로봇 동작의 중복 생성/실행 없음 |
| 장애 복구 | 워커 중단·네트워크 단절 시 상태 추적 | 과거 실행의 늦은 결과로 현재 상태 변경 불가 |
| 관측성 | 식별자와 실패 사유 추적 | episode·job·version·deployment 간 이력 연결, secret 미기록 |
| 상태 표시 | 변경 후 웹에 갱신 결과 표시 | 제안: 서버 상태 반영 후 5초 이내 화면 반영. 측정 구간 명시 |
| 일반 API | 파일 전송·학습을 제외한 요청 응답 | 제안: 합의된 부하에서 p95 1초 이내. 동시 사용자·데이터량은 별도 확정 |
| 호환성 | 모델과 로봇 실행 환경 확인 | 미지원 형식·런타임·입출력 스키마 배포 차단 |
| 평가 재현성 | 모델·환경·시드·소프트웨어 버전 기록 | 재실행 입력 재구성 가능. GPU·물리 연산의 비결정성까지 동일 결과 보장하지 않음 |
| 실행 격리 | 가상 실행과 실제 로봇의 명령·권한 분리 | 시뮬레이션에서 실제 제어 경로 접근 차단 |
| 안전 | 로컬 안전 정지 및 시작 조건 | 인터넷 연결과 무관한 정지 수단, 통신 두절·잘못된 명령 시 안전 동작 검증 |

센서 주기·추론 지연·모터 제어 주기·정지 시간은 실제 하드웨어와 작업 위험도를 기준으로 별도 정한다. 위 웹 응답 목표를 로봇 제어 성능 목표로 사용하지 않는다.

| 지표 | 측정 방식 | 제안 목표 또는 결정 기준 |
|---|---|---|
| 핵심 흐름 완주 | 시연 등록 → 학습 → 시뮬레이션 결과 → 승인 → 배포 확인 통합 실행 | 합의된 정상 시나리오 3회 연속 통과 |
| 리소스 추적성 | 배포 결과에서 모델·학습·입력으로 역추적 | 평가 대상 배포 전부 연결 가능 |
| 접근 통제 | 계정·장치·서비스 역할별 부정 접근 테스트 | 정의된 테스트 전부 차단 |
| 파일 무결성 | 손상·누락·해시 불일치 파일 테스트 | 학습·배포 사용 차단 |
| 재요청 안전성 | 중복 등록·작업 생성·명령 수신 테스트 | 중복 리소스 및 중복 로봇 동작 없음 |
| 상태 복구 | 새로고침·재연결·워커 중단 테스트 | REST 조회로 현재 상태 확인, 늦은 보고에 의한 상태 역행 없음 |
| 시뮬레이션 MVP 완주 | 준비된 모델로 평가 실행·지표·재생 자료·판정 조회 | 정상 통합 시나리오 3회 통과 제안. 정책 성공률과 별개 |
| sim-to-real 효과 | 기준 모델과 전이 모델의 독립 실제 평가 비교 | 목표 개선폭·시도 수는 실험 전 확정. 개선을 사전 보장하지 않음 |
| 로봇 작업 성과 | 고정 환경·평가 데이터·시도 횟수로 측정 | 목표 성공률·시도 횟수는 AI/HW 사전 실험 후 확정 |
| 안전 검증 | 정지·통신 단절·실패 배포·재시작 시나리오 | 합의한 안전 절차 모두 통과 |

**물리 로봇을 포함하는 출시 승인은 작업 성과 기준과 안전 기준을 확정하고 통과한 뒤에만 가능하다.** 모델 파일 다운로드 성공만으로 전체 제품 성공을 판정하지 않는다.

## 15. 1차 MVP — UMI 학습 결과 시뮬레이션 테스트

### 15.1 목적과 제외 범위

**실제 UMI 시연으로 학습한 고정 모델을 가상 환경에서 실행하여, 실물 적용을 검토할 수 있는 평가 기록을 만든다.**

저장된 시연 영상을 재생하거나 정해진 로봇 동작을 애니메이션으로 보여주는 것만으로 이 요구를 충족하지 않는다. 모델이 가상 센서 관측을 받아 행동을 출력하고, 행동으로 바뀐 환경을 다시 관측하는 실행 루프를 제공해야 한다.

1차 MVP에는 합성 데이터로 새 모델을 학습하는 기능, 범용 장면 편집기, 모든 로봇 지원, 브라우저 내 실시간 3D 렌더링을 필수로 포함하지 않는다. 결과 영상 또는 재생 가능한 실행 기록으로 테스트 결과를 확인할 수 있다.

### 15.2 평가 입력·출력 계약

| 구분 | 필수 정보 |
|---|---|
| 대상 모델 | 모델 버전 ID, 실제 사용 artifact 해시, 정책 런타임·입출력 스키마 |
| 가상 환경 | 시뮬레이터·자산·로봇·그리퍼·카메라·장면 설정 버전 |
| 어댑터 | 관측 전처리, 카메라 규격, 좌표계, 행동 단위·스케일·주기, 그리퍼 매핑 |
| 시나리오 | 작업 목표, 초기 상태, 물체 배치, 종료·성공·실패 조건 |
| 실행 설정 | 시드 목록, 반복 횟수, 최대 스텝/시간, 자원 제한 |
| 판정 설정 | 평가 스위트 버전, 최소 유효 시행 수, 성공률·충돌 등 임계값 |
| 결과 | 시행별 결과, 집계 지표, 판정, 오류, 시작·종료 시각, 실행 버전 |
| 산출물 | 영상 또는 재생 기록, 지표 파일, 오류 로그, 저장 위치·해시 |

체크포인트에 시뮬레이터가 기본 제공하는 정답 상태를 임의로 입력해 성능을 높여서는 안 된다. 평가용 관측은 실제 정책이 사용하도록 설계된 관측과 맞추고, 시뮬레이터의 정답 상태를 판정에만 사용하는 경우 이를 구분한다.

### 15.3 시행 및 평가 판정

| 구분 | 정의 | 집계 처리 |
|---|---|---|
| 성공 | 미리 정의한 작업 목표·종료 조건 만족 | 유효 시행의 성공 수에 포함 |
| 정책 실패 | 정상 실행 중 목표 미달·제한 시간 초과·금지 접촉 등 | 유효 시행의 실패 수에 포함 |
| 시스템 오류 | 환경 로드 실패·런타임 오류·워커 장애 등 | 정책 성패 분모에서 제외하되 오류 수·비율을 별도 공개 |
| 취소 | 사용자 또는 운영 정책으로 실행 중단 | 완료된 부분 결과를 보존하고 평가 미완결 표시 |

- **작업 성공률 = 성공 시행 수 / 유효 시행 수.** 유효 시행은 성공 + 정책 실패다.
- 요청 시행 수, 유효 시행 수, 오류 수, 취소 수를 함께 표시한다. 유효 시행이 0이면 성공률을 0%가 아닌 N/A로 표시한다.
- **충돌 발생률 = 금지 충돌이 한 번 이상 발생한 유효 시행 수 / 유효 시행 수.** 물체를 잡기 위한 정상 접촉과 금지 충돌을 시나리오에서 구분한다.
- 완료 시간은 성공 시행을 기준으로 요약하며, 평가의 시뮬레이션 시간과 워커의 실제 소요 시간을 구분한다.
- PASS는 최소 유효 시행 수와 모든 필수 임계값을 충족한 경우에만 부여한다. 충분히 평가했으나 기준 미달이면 FAIL이다.
- 기준 미확정, 유효 시행 부족, 필수 지표 누락, 완료되지 않은 평가는 INCONCLUSIVE로 표시하며 자동 승인하지 않는다.
- 시스템 오류가 많아 일부 성공 시행만 남은 경우에도 최소 시행 수·허용 오류율 기준을 적용한다.
- 테스트 반복 횟수·성공률·허용 충돌·오류율 수치는 대표 작업 검증 후 첫 정식 평가 전에 고정한다. 결과를 보고 기준을 바꾸면 새 스위트 버전으로 기록한다.

### 15.4 배포 검토 규칙

1. 평가 결과는 모델 버전만이 아니라 실제 artifact 해시·환경/스위트·어댑터 버전에 묶인다.
2. 로봇 프로파일에 요구 평가 스위트를 연결하고, 다른 작업·로봇 환경에서의 통과를 대신 사용하지 않는다.
3. 모델 파일·행동 어댑터·환경의 관련 설정 변경 시 영향받는 평가를 다시 수행한다.
4. 배포용 모델 변환이 평가 이후 이루어지면 변환본의 일치성 검증 또는 재평가 결과를 별도로 연결한다.
5. 모델 파일 READY, 시뮬레이션 PASS, 운영자 배포 승인, 로컬 적용 성공은 별도 상태다.
6. 평가 통과는 로봇 자동 시작 명령이 아니다. 실제 시작은 로컬 안전 조건과 승인 절차를 따른다.

### 15.5 1차 MVP 인수 시나리오

| 시나리오 | 기대 결과 |
|---|---|
| 정상 모델·환경으로 평가 | 모델 기반 실행 후 지표·재생 자료·판정 조회 |
| 관측·행동 스키마 불일치 | 실행 전 차단하고 불일치 필드 표시 |
| 모델이 목표 달성 실패 | 평가 작업은 완료되지만 정책 실패로 집계 |
| 워커 장애 | 시스템 오류로 기록, 작업 재시도 시 원본 실행 이력 유지 |
| 중복 평가 요청·보고 | 같은 요청에서 평가 작업 중복 생성 방지, 이전 시도의 결과 덮어쓰기 차단 |
| 평가 중 취소 | 실제 중단 확인 및 부분 결과 보존, PASS 부여 금지 |
| 모델 변경 후 이전 PASS로 배포 요청 | 이전 평가 사용 차단 |
| 평가 페이지 새로고침 | 현재 상태·시행 결과·영상/로그 링크 복구 |

## 16. 후속 단계 — sim-to-real 기반 UMI 학습

### 16.1 목적

**실제 UMI 시연과 시뮬레이션에서 확보한 학습 정보를 활용하여 모델을 학습·보완하고, 그 효과를 실제 로봇에서 검증한다.**

본 문서에서 “UMI 학습”은 UMI 장치 자체를 학습시킨다는 뜻이 아니라 UMI 시연을 활용하는 로봇 정책 학습을 의미한다. sim-to-real은 정해진 단일 알고리즘이나 성능 개선 보장이 아니라 실험·데이터·배포·실제 평가를 연결하는 후속 제품 기능이다.

### 16.2 실험 흐름

| 단계 | 수행 내용 | 기록할 결과 |
|---|---|---|
| 1. 기준 모델 고정 | 실제 UMI 데이터로 학습한 비교 대상 선택 | 학습 데이터·설정·모델 해시 |
| 2. 환경 구성 | 대상 로봇·물체·센서·작업 조건 설정 | 환경 버전·실제 대응 관계 |
| 3. 학습 데이터 생성 | 선택한 전문가 정책·계획기·가상 시연 등으로 데이터 생성 | 생성 방식·관측·행동 라벨·성패·품질 |
| 4. 변동 조건 설정 | 선택한 시각·배치·물리 파라미터 범위 변화 | 파라미터 범위·시드·생성 분포 |
| 5. 데이터 구성 | 실측·합성 데이터 검증 및 분할 | 출처·데이터 버전·선별 기준·혼합 비율 |
| 6. 학습/보완 | 선택한 사전학습·혼합학습·미세조정 방법 실행 | 입력 구성·부모 모델·방법·새 버전 |
| 7. 독립 시뮬레이션 평가 | 학습·튜닝에 쓰지 않은 평가 조건으로 실행 | 평가 지표·조건·판정 |
| 8. 실제 전이 평가 | 승인된 후보를 실제 로봇에서 기준 모델과 비교 | 성공 수·시도 수·시간·안전 사건 |
| 9. 차이 분석 | 실제 실패와 가상 결과의 차이 검토 | 개선·악화·추가 데이터 필요 사항 |

단순히 시뮬레이션 평가에 성공한 영상만 모은 것을 학습 데이터로 간주하지 않는다. 필요한 관측·행동 라벨과 생성 품질이 학습 방식에 맞는지 검증한다. 재학습 방식은 기술 실험으로 결정하며 강화학습 사용을 필수로 가정하지 않는다.

### 16.3 데이터·실험 관리

| 요구 | 수용 기준 |
|---|---|
| 출처 구분 | 실제 UMI/시뮬레이션 생성/파생 데이터 구분 |
| 시뮬레이션 데이터 귀속 | 실제 UMI 캡처 ID를 허위 발급하지 않고 별도 데이터셋으로 관리. 대상 작업·모델과 연결 |
| 변환 이력 | 실제·가상 데이터의 전처리·좌표 변환·단위·필터링 버전 기록 |
| 학습 구성 | 실측/합성 혼합 비율 및 실제 사용 샘플 수 기록 |
| 부모 모델 연결 | 기존 모델에서 이어 학습한 경우 부모 버전·데이터 연결 |
| 평가 분리 | 최종 평가 환경·시드·실제 평가 데이터의 학습 편입 방지 |
| 데이터 재사용 | 평가 결과를 개발에 사용하기로 하면 개발 데이터로 재분류하고 새로운 독립 최종 평가 준비 |
| 실험 실패 보존 | 성능 악화·학습 실패·전이 실패도 삭제하지 않고 결과로 기록 |

### 16.4 실제 비교 평가

- 기준 모델과 후보 모델의 대상 로봇·물체·작업 정의·성공 판정·시도 수를 사전에 맞춘다.
- 반복 순서·초기 조건·시드 적용 가능 범위 등 비교 설계를 기록하고 실험 중 변경 사항을 공개한다.
- 실제 성공률은 각 모델의 성공 수/유효 시도 수로 표시하며, 유효 시도 수와 오류·중단 수를 함께 제시한다.
- 성공률 차이는 퍼센트포인트로 계산하고 표본 수와 함께 표시한다. 작은 표본에서 일반적인 개선을 단정하지 않는다.
- 학습 데이터량·학습 자원·튜닝 횟수가 다르면 이를 명시한다. 어떤 요인 때문에 개선되었는지 분리할 필요가 있으면 추가 대조 실험을 설계한다.
- 실제 성능이 나빠지거나 안전 기준을 위반하면 후보 승인을 보류하고 기존 모델을 유지한다.
- 전이 성과 목표·실물 평가 횟수·안전 기준은 실험 전에 확정한다. 플랫폼이 비교 결과를 기록하는 기능의 완료와 모델 개선 성공을 별도로 판정한다.

## 17. 인터페이스 확장 범위

아래는 제품 기능을 위한 API 그룹 제안이며 상세 요청·응답 계약은 별도로 작성한다. 기존 API가 구현되어 있다고 가정하지 않는다.

| 그룹 | 필요한 기능 | 단계 |
|---|---|---|
| 시뮬레이션 환경 | 등록된 환경·로봇 프로파일·평가 스위트 목록/버전 조회 | 1차 |
| 시뮬레이션 평가 | 실행 생성·목록·상세·취소·재시도 | 1차 |
| 평가 산출물 | 시행별 지표·판정·영상/로그의 권한 있는 조회 | 1차 |
| 시뮬레이션 워커 내부 | 작업 할당·임대·진행/오류 보고·산출물 등록 | 1차 |
| 배포 승인 연계 | 해당 모델·대상 환경 평가 근거 확인 및 승인 | 1차 |
| 합성 데이터셋 | 생성 작업·출처·품질·분할·버전 관리 | 후속 |
| 전이 학습 | 데이터 구성·학습 방법·부모 모델 지정 및 실행 | 후속 |
| 실제 평가 | 비교 실험·시도별 결과·기준/후보 모델 비교 | 후속 |

시뮬레이션 워커는 사용자·GPU 학습 워커·실제 Jetson과 역할을 구분해 인증한다. 작업 ID·attempt·멱등성 키 및 산출물 해시 등 기존 신뢰성 원칙을 평가·데이터 생성 작업에도 적용한다.

이 문서는 기존 PRD를 보존한 시뮬레이션 확장안이다. 1차 테스트 MVP와 후속 sim-to-real 학습을 구분했으며, 시뮬레이터 선택·실제 성능·하드웨어 호환성은 아직 검증하지 않았다.

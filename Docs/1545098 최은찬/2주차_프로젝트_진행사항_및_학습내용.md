### 1. UMI 학습 방식 및 작동 방식

#### UMI의 기본 개념

UMI(Universal Manipulation Interface)는 **사람의 작업 시연을 수집하여 로봇의 동작 학습에 활용하는 인터페이스**다. 사람이 작업을 보여주면, 그 과정에서 얻은 데이터를 바탕으로 로봇이 작업 수행 방법을 학습한다.

이번 학습에서는 개별 장치뿐 아니라 **데이터 수집부터 학습된 모델의 로봇 적용까지 이어지는 전체 흐름**을 이해하는 데 중점을 두었다.

#### 학습 및 작동 흐름

| 단계 | 주요 내용 |
|---|---|
| 시연 데이터 수집 | 사람이 작업을 수행하면서 영상과 동작 관련 데이터를 수집한다. |
| 데이터 정리 | 수집한 데이터의 누락 여부와 시간 정렬 등을 확인하고 학습에 사용할 형태로 구성한다. |
| 모델 학습 | 준비된 시연 데이터를 사용하여 작업 수행에 필요한 동작을 학습한다. |
| 모델 적용 | 학습 결과를 로봇 실행 환경에 맞게 준비하고 적용한다. |
| 실행 및 확인 | 로봇의 실제 작업 수행 결과를 확인하고 개선할 부분을 찾는다. |

#### 주요 학습 내용

- **데이터 간 시간 동기화:** 영상과 센서 정보가 같은 시점의 상황을 나타내도록 정렬하는 것이 중요하다.
- **데이터 품질:** 파일 업로드 성공 여부뿐 아니라 누락·손상·형식·시간 정보도 확인해야 한다.
- **학습 환경과 실행 환경의 차이:** 학습 데이터를 수집한 조건과 실제 로봇이 작업하는 조건의 차이를 고려해야 한다.
- **단계별 상태 구분:** 데이터 준비, 모델 학습, 로봇 적용은 서로 다른 과정이므로 각각의 진행 상태를 관리해야 한다.

#### 프로젝트에 적용할 내용

이번 프로젝트에서는 시연 데이터를 **영상·IMU·메타데이터가 묶인 단위**로 관리하는 방향으로 설계했다. 이는 프로젝트의 데이터 구성안이며, 구체적인 필수 데이터와 전처리 방식은 사용할 UMI 학습 파이프라인에 맞춰 확정해야 한다.

또한 다음 상태를 구분해 관리할 필요가 있다.

**업로드 완료 → 데이터 검증 완료 → 학습 완료 → 모델 배포 완료 → 로봇 적용 완료**

### 2. ROS 2 구동 방식 및 특장점

#### 기본 구조와 구동 방식

ROS 2 학습에서는 **하나의 프로그램이 모든 기능을 담당하기보다, 역할별 노드가 통신하며 로봇 시스템을 구성하는 방식**을 중심으로 이해하였다.

| 구성 요소 | 학습한 내용 |
|---|---|
| 노드(Node) | 센서 입력, 모델 추론, 로봇 제어 등 개별 기능을 담당하는 실행 단위 |
| 패키지(Package) | 관련 코드·설정·실행 파일을 묶어 관리하는 단위 |
| 런치 파일(Launch File) | 여러 노드와 실행 설정을 함께 구성하는 방법 |
| 토픽(Topic) | 센서값처럼 지속적으로 발생하는 데이터를 전달하는 통신 방식 |
| 서비스(Service) | 요청을 보내고 응답을 받는 통신 방식 |
| 액션(Action) | 시간이 걸리는 작업의 진행 상황과 결과를 다루고 취소를 요청하는 방식 |

#### 주요 학습 내용

- **역할 분리:** 센서 데이터 처리, 추론, 제어 기능을 구분하여 구성하는 방법을 이해하였다.
- **통신 방식 선택:** 연속적인 데이터 전달과 단발성 요청, 장시간 작업을 같은 방식으로 처리하지 않고 목적에 맞게 구분해야 한다.
- **실행 구성:** 패키지와 런치 파일을 활용하여 여러 노드를 실행하는 흐름을 살펴보았다.
- **QoS 이해:** 데이터의 전달 특성에 맞는 통신 정책을 고려해야 한다는 점을 학습하였다.

#### 특장점

| 특장점 | 의미 |
|---|---|
| 모듈화 | 기능별로 나누어 개발하고 수정할 수 있다. |
| 분산 구성 | 여러 프로세스와 장치 사이의 통신을 바탕으로 시스템을 구성할 수 있다. |
| 기능 재사용 | 역할이 분리된 구성 요소를 다른 작업에도 활용하기 쉽다. |
| 통신 정책 설정 | 센서 데이터와 작업 명령의 특성에 맞춰 통신 방식을 검토할 수 있다. |

#### 프로젝트에 적용할 내용

프로젝트에서는 **웹·백엔드의 작업 관리와 로봇 내부의 제어 역할을 구분**하는 것이 중요하다.

- **웹·백엔드:** 학습 요청, 모델 관리, 배포 요청, 작업 실행 요청 및 상태 조회
- **Jetson·로봇 내부:** 센서 입력 처리, 모델 추론, 로봇 제어와 실행 상태 보고

향후에는 이 역할 분리를 기준으로 ROS 2 노드와 통신 흐름을 구체화할 수 있다. 특히 **웹에서 중지 요청을 접수한 상태와 로봇이 실제로 정지한 상태를 구분**하고, 로컬 안전 제어도 별도로 고려해야 한다.

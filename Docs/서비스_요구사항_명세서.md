# 서비스 요구사항 명세서

| 항목 | 내용 |
|---|---|
| 서비스명 | SSAFY : Smart Solutions All For You |
| 작성일 | 2026-09-28 |
| 작성 기준 | `dev` 브랜치 `519aeeb`의 소스 코드 |
| 범위 | 수집 앱, 웹, EC2 백엔드, GPU 학습 서버, Jetson 로봇 |

이 문서는 현재 코드에 구현된 기능을 기준으로 서비스 요구사항을 정리한 것입니다. 기획 단계에서 쓴 초안은 [PRD](PRD.md)에 있습니다.

## 1. 개요

### 1.1 서비스 소개

사람이 손에 드는 수집 장치(UMI)로 작업을 직접 시연하면, 그 영상과 센서 기록으로 로봇이 할 동작을 학습합니다. 사용자는 웹에서 학습된 동작을 블록처럼 조립해 작업을 만들고, 로봇 팔(SO-101)에 적용해 실행합니다.

### 1.2 전체 흐름

1. **수집**: 수집 앱으로 시연을 촬영해 업로드합니다.
2. **검증**: EC2 백엔드가 업로드된 파일 구성과 센서 데이터를 검사해 에피소드로 등록합니다.
3. **학습 요청**: 웹에서 동작과 에피소드를 골라 학습을 요청합니다.
4. **학습**: GPU 서버가 작업을 가져가 전처리(ORB-SLAM3)와 UMI Diffusion Policy 학습을 하고 결과 모델을 등록합니다.
5. **작업 구성**: 웹 블록 편집기에서 학습된 동작, 모터, 반복 블록으로 작업을 만듭니다.
6. **적용·실행**: 작업을 로봇에 적용하면 Jetson이 모델을 받아 설치하고, 실행 명령에 따라 로봇 팔을 움직입니다.

### 1.3 구성 요소

| 구성 요소 | 소스 | 역할 |
|---|---|---|
| 수집 앱 (SSAFY Collect) | `APP/collect` | 시연 촬영·업로드, 로봇용 카메라 송출 |
| 웹 | `FE` | 장치·데이터·학습·작업·로봇 관리 화면 |
| EC2 백엔드 | `BE/EC2_` | 인증, 데이터·학습·모델·배포·실행 관리, 로봇 명령 전달 |
| GPU 학습 서버 | `BE/GPU_` | 학습 입력 준비, 전처리, 학습, 모델 등록 |
| 로봇 (Jetson) | `ROS` | 명령 수신, 모델 설치, 정책 추론, 서보 제어 |
| 파일 저장소 | AWS S3 | 에피소드 ZIP, 모델 패키지 보관 |

### 1.4 사용자

| 사용자 | 설명 |
|---|---|
| 웹 사용자 | 계정으로 로그인해 장치 등록, 학습 요청, 작업 구성, 로봇 적용과 실행을 하는 사람 |
| 수집자 | 수집 앱을 단 UMI로 시연을 촬영하는 사람. 앱은 계정 로그인 없이, 웹에서 등록한 장치 자격으로 동작한다 |
| GPU 워커 | EC2에서 학습 작업을 가져가 처리하는 서버 (시스템) |
| 로봇 | EC2에 등록된 Jetson 장치 (시스템) |

### 1.5 용어

| 용어 | 뜻 |
|---|---|
| UMI | 손에 드는 그리퍼에 스마트폰을 달아 사람의 작업 시연을 기록하는 장치 |
| 에피소드 | 시연 한 번의 기록(영상, 프레임 정보, IMU). 앱에서 ZIP 하나로 올린다 |
| Mapping / Demonstration | 학습 입력 에피소드의 역할. Mapping은 작업 공간 지도(SLAM Atlas)를 만드는 영상이고, Demonstration은 실제 작업 시연이다 |
| 동작(스킬) | 로봇이 배울 작업 단위. 학습이 끝나면 동작의 새 버전(모델)이 생긴다 |
| 모델 패키지 | 학습 결과 파일(encoder.pt, denoiser.pt, metadata.json 등)을 비압축 TAR로 묶은 것 |
| 게이트 | 모델을 로봇에 배포해도 되는지 평가 결과로 판정하는 기준 |
| 작업(Task) | 동작(SKILL), 모터(MOTOR), 반복(REPEAT) 블록을 조립한 로봇 작업. 저장할 때마다 버전이 생긴다 |
| 배포 | 작업 버전과 작업에 필요한 모델을 로봇에 설치하는 것 |
| 실행 | 배포된 작업을 로봇에서 한 번 수행하는 것 |
| lease | GPU 워커가 학습 작업을 맡고 있다는 표시. 제때 연장하지 않으면 작업이 다시 대기열로 돌아간다 |

## 2. 기능 요구사항

중요도는 다음 기준으로 매겼습니다.

- **상**: 수집 → 학습 → 배포 → 실행으로 이어지는 핵심 흐름에 꼭 필요한 기능
- **중**: 운영과 안정성을 위한 기능
- **하**: 편의 기능

### 2.1 회원·인증

| ID | 요구사항명 | 상세 내용 | 중요도 | 관련 모듈 |

| FR-AUTH-04 | 로그아웃 | 세션과 쿠키를 삭제하고, 같은 브라우저의 다른 탭도 함께 로그아웃한다. | 중 | FE, BE/EC2_ |

## 3. 비기능 요구사항

### 3.1 보안

| ID | 요구사항명 | 상세 내용 |
|---|---|---|
| NFR-SEC-01 | 사용자 인증 | 접근 토큰은 JWT(HS256, 15분)이고, 요청마다 Redis의 로그인 세션을 확인한다. 갱신 쿠키는 HttpOnly·Secure·SameSite=Lax로 발급하고, 쿠키를 쓰는 요청은 허용된 Origin과 `X-Session-Request` 헤더를 확인한다. |
| NFR-SEC-02 | 비밀 정보 저장 | 비밀번호와 장치 secret은 BCrypt로, QR 등록 토큰과 작업 점유(lease) 토큰은 SHA-256 해시로 저장한다. 장치 secret은 발급할 때 한 번만 보여준다. 앱은 secret을 AndroidKeyStore로 암호화해 보관하고, 로봇은 권한 600인 `.env` 파일에 두며 git에 올리지 않는다. |
| NFR-SEC-03 | 사용자별 데이터 분리 | 장치, 에피소드, 학습, 작업, 로봇은 소유자만 조회하고 사용할 수 있다. 다른 사용자의 장치로 업로드하거나 다른 사용자의 에피소드로 학습할 수 없다. |
| NFR-SEC-04 | 전송 보안 | 외부 통신은 HTTPS(TLS 1.2/1.3, HSTS)로 한다. 파일은 서버가 발급한 유효 15분짜리 S3 presigned URL로만 주고받고, 앱·GPU 서버·로봇에는 AWS 키를 두지 않는다. S3에 올릴 때는 SHA-256 체크섬 헤더를 붙인다. 앱은 평문 HTTP를 localhost에만 허용한다. |
| NFR-SEC-05 | GPU 서버 내부 보호 | GPU 서버 안의 Spring과 학습 API는 서로 Bearer 토큰으로 인증한다. 학습 API와 전처리 API는 127.0.0.1에만 열어 외부에서 접근할 수 없게 한다. |
| NFR-SEC-06 | 로그 보호 | 모든 응답에 요청 ID(`X-Request-Id`)를 붙이고, 로그에서 비밀값을 가린다. |

### 3.2 신뢰성

| ID | 요구사항명 | 상세 내용 |
|---|---|---|
| NFR-REL-01 | 중복 요청 방지 | 생성·실행 요청은 멱등 키(`Idempotency-Key`)로 한 번만 처리하고, 키는 24시간 보관한다. 같은 키로 다른 내용이 오면 거부한다. 앱은 재시도할 때 같은 세션 ID와 멱등 키를 쓰고, 로봇은 같은 명령을 한 번만 처리한다. |
| NFR-REL-02 | 순서 보장 | 로봇 보고는 reportId와 순서 번호로, GPU 이벤트는 eventId와 순서 번호로 중복과 역순을 막는다. |
| NFR-REL-03 | 재시도 | 앱 업로드는 30초부터 간격을 늘려 다시 시도한다. GPU 서버는 보낼 이벤트를 파일에 먼저 기록하고, 보내지 못하면 간격을 늘려 다시 보낸다. 로봇은 명령 스트림이 끊기면 3초부터 간격을 늘려 다시 연결한다. |
| NFR-REL-04 | 장애 복구 | GPU 워커가 멈춰 작업 점유가 끝나면 작업을 다시 배정한다. GPU 서버는 재시작 후 진행 중이던 모델 업로드와 완료 처리를 이어서 한다. 로봇은 재시작 후 현재 배포를 복구하고, 서버는 로봇이 다시 연결하면 진행 중인 명령을 다시 보낸다. |
| NFR-REL-05 | 데이터 무결성 | 에피소드, 학습 데이터, 모델 패키지는 전달 단계마다 크기와 SHA-256을 확인한다. |
| NFR-REL-06 | 동시 실행 제어 | 로봇 한 대에서는 배포와 실행을 한 번에 하나씩만 한다. 학습 작업은 DB 잠금으로 한 워커에만 배정하고, 로봇 프로그램은 한 기기에서 하나만 뜨도록 막는다. |

### 3.3 성능·용량

| ID | 요구사항명 | 상세 내용 |
|---|---|---|
| NFR-PERF-01 | 업로드 용량 | 에피소드 ZIP은 200MB 이하, 압축을 푼 크기도 200MB 이하, 항목 64개 이하로 한다. |
| NFR-PERF-02 | 수집 품질 | 영상은 1920×1080, 30fps로, IMU는 200Hz로 기록한다. |
| NFR-PERF-03 | 상태 갱신 | 웹은 배포·실행 상태를 2초, 학습 상세를 3초, 실행 중인 작업 카드를 5초마다 갱신한다. 장치 연결 상태는 heartbeat 주기(15초)로 갱신한다. |
| NFR-PERF-04 | GPU 처리 | GPU 서버 하나는 학습 1건과 전처리 1건을 동시에 처리한다. 전처리가 30분을 넘으면 중단하고 실패로 처리한다. |

### 3.4 로봇 안전

| ID | 요구사항명 | 상세 내용 |

## 4. 인터페이스 요구사항

| ID | 구간 | 방식 | 주요 내용 |
|---|---|---|---|
| IF-01 | 웹 ↔ EC2 | HTTPS REST (`/api/v1`) | 사용자 JWT. 응답은 `{data}`, 오류는 `{code, message}` 형식 |
| IF-02 | 수집 앱 ↔ EC2 | HTTPS REST | 장치 토큰. QR 등록, 토큰 발급, 동작 목록, 업로드 요청·완료 |
| IF-03 | 수집 앱 → S3 | presigned PUT | `x-amz-checksum-sha256`, `If-None-Match: *` 헤더 |
| IF-04 | GPU 서버 → EC2 | HTTPS REST (`/internal`) | 저장 노드 등록·상태 보고, 작업 가져가기, lease 연장, 진행 이벤트, 모델 등록. EC2가 GPU 서버를 먼저 호출하지 않는다 |
| IF-05 | GPU 서버 ↔ S3 | presigned GET / PUT | 에피소드 내려받기, 모델 패키지 올리기 |
| IF-06 | GPU 서버 내부 | HTTP | Spring ↔ 학습 API(Bearer 토큰), Spring → 전처리 API |
| IF-07 | EC2 → 로봇 | SSE (`/robots/me/command-stream`) | 이벤트 `robot.command`로 배포·실행·취소 명령 전달 |
| IF-08 | 로봇 → EC2 | HTTPS REST | heartbeat, 배포 정보 조회와 URL 재발급, 배포·실행 보고 |
| IF-09 | 로봇 ← S3 | presigned GET | 모델 패키지 내려받기 |
| IF-10 | 수집 앱 → 로봇 | USB(adb 포트 연결), TCP 8765 | 로봇이 1바이트 요청을 보내면 앱이 `UMI1` 헤더와 JPEG 프레임 1장을 보낸다 |
| IF-11 | 로봇 → 서보 | UART, 1Mbps | ST3215 프로토콜로 위치 명령을 보내고 상태를 읽는다 |

## 5. 상태 정의

웹, EC2, GPU 서버, 로봇은 아래 상태값을 함께 씁니다. 완료·실패·취소처럼 끝난 상태가 되면 더는 바뀌지 않습니다.

### 5.1 장치

| 구분 | 상태 | 뜻 |
|---|---|---|
| 등록 | PENDING | 웹에서 UMI를 추가했지만 아직 앱으로 QR 등록을 하지 않은 상태. 장치 목록에 나오지 않는다 |
| 등록 | REGISTERED | 등록이 끝난 상태. 로봇은 추가하는 즉시 이 상태가 된다 |
| 등록 QR | ACTIVE | 쓸 수 있는 QR |
| 등록 QR | USED | 앱이 이 QR로 등록을 마친 상태 |
| 등록 QR | EXPIRED | 유효시간(10분)이 지난 상태 |
| 등록 QR | REVOKED | 5번 틀렸거나 새 QR을 만들어 폐기된 상태 |
| 연결 | ONLINE / OFFLINE | 45초 안에 heartbeat를 받았는지로 판정한다 |

### 5.2 업로드 세션

| 상태 | 뜻 | 다음 상태 |
|---|---|---|
| UPLOAD_PENDING | 업로드 URL을 발급하고 파일을 기다리는 중 | VALIDATING, CANCELLED |
| VALIDATING | 완료 통지를 받고 파일을 검증하는 중 | READY, INVALID, FAILED |
| READY | 검증을 통과해 에피소드로 등록됨 | 끝 |
| INVALID | 파일 구성이나 내용이 규칙에 맞지 않음 | 끝 |
| FAILED | 서버 처리 중 오류. 완료 통지를 다시 보내면 다시 검증한다 | VALIDATING |
| CANCELLED | 업로드 전에 취소함. S3에 올라간 파일도 지운다 | 끝 |

### 5.3 학습

| 상태 | 뜻 | 이 상태가 되는 때 |
|---|---|---|
| QUEUED | GPU 배정을 기다리는 중 | 학습을 요청했을 때, 또는 작업 점유(lease)가 끊겨 다시 대기열에 들어갔을 때 |
| PREPARING | 입력 준비와 전처리 중 | GPU 서버가 작업을 가져갔을 때 |
| RUNNING | 학습 중 | GPU 서버가 학습 시작을 알렸을 때 |
| MODEL_UPLOADING | 학습이 끝나 모델을 올리는 중 | GPU 서버가 학습 완료를 알리거나 모델 업로드를 시작했을 때 |
| MODEL_VALIDATING | 올라온 모델을 검증하는 중 | GPU 서버가 모델 업로드 완료를 알렸을 때 |
| SUCCEEDED | 모델을 쓸 수 있음 | 모델 검증을 통과했을 때 |
| FAILED | 실패 | GPU 서버가 실패를 알렸거나, 모델 검증에 실패했거나, 작업 점유가 세 번 끊겼을 때 |
| CANCEL_REQUESTED | 취소를 GPU 서버에 전달하는 중 | GPU에 배정된 뒤 사용자가 취소했을 때 |
| CANCELED | 취소됨 | GPU 배정 전에 취소했거나, GPU 서버가 취소 완료를 알렸거나, 취소 요청 중에 작업 점유가 끊겼을 때 |

### 5.4 모델 (동작 버전)

| 상태 | 뜻 |
|---|---|
| UPLOADING | GPU 서버가 모델 패키지를 올리는 중 |
| VALIDATING | EC2가 모델 패키지의 크기·SHA-256·구성을 검증하는 중 |
| READY | 검증 통과. 게이트까지 통과하면 로봇에 배포할 수 있다 |
| FAILED | 검증 실패 |

### 5.5 배포

| 상태 | 뜻 | 바꾸는 쪽 |
|---|---|---|
| PENDING | 배포를 요청하고 로봇에 명령을 보낸 상태 | EC2 |
| DOWNLOADING | 로봇이 모델을 내려받는 중 | 로봇 |
| VERIFYING | 로봇이 크기와 SHA-256을 확인하는 중 | 로봇 |
| APPLYING | 로봇이 모델을 풀어 설치하는 중 | 로봇 |
| SUCCEEDED | 설치 완료. 이 배포가 로봇의 현재 배포가 된다 | 로봇 |
| FAILED | 실패. 요청 후 30초 동안 로봇이 진행을 보고하지 않아도 이 상태가 된다 | 로봇, EC2 |

- 순서는 PENDING → DOWNLOADING → VERIFYING → APPLYING → SUCCEEDED이고, FAILED는 끝나기 전 어느 단계에서든 될 수 있다.
- 배포 안의 모델별 항목은 PENDING → DOWNLOADING → VERIFIED 또는 FAILED로 바뀐다. 모든 항목이 VERIFIED여야 배포가 SUCCEEDED가 될 수 있다.

### 5.6 실행

| 상태 | 뜻 | 바꾸는 쪽 |
|---|---|---|
| REQUESTED | 실행을 요청하고 로봇에 명령을 보낸 상태 | EC2 |
| STARTING | 로봇이 실행을 시작함 | 로봇 |
| RUNNING | 단계를 실행하는 중 | 로봇 |
| SUCCEEDED | 모든 단계를 마침(진행률 100%) | 로봇 |
| FAILED | 실패. 오류 내용을 함께 보고한다 | 로봇 |
| CANCEL_REQUESTED | 사용자가 중지해 로봇에 취소 명령을 보낸 상태 | EC2 |
| CANCELED | 취소됨 | EC2(시작 전 중지), 로봇 |

- 순서는 REQUESTED → STARTING → RUNNING → SUCCEEDED이다.
- 중지하면 REQUESTED는 바로 CANCELED가 되고, STARTING·RUNNING은 CANCEL_REQUESTED를 거쳐 로봇이 멈춘 뒤 CANCELED가 된다.
- FAILED는 끝나기 전 어느 단계에서든 될 수 있다. 진행 중에는 같은 상태로 여러 번 보고하면서 현재 단계와 진행률을 갱신한다.

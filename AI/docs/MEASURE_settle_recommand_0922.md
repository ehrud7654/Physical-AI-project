## 1. settle_timeout 은 경계값이었다 🟢

```
0.5 초  remaining {1:-1, 2:347, 3:-73, 4:-255, 5:-4, 6:167}   최악 347틱 → timeout 사망
3.0 초  remaining {1: 1, 2:-1, 3:-26, 4:-12, 5: 1, 6: 2}      최악  26틱 → timeout 사망
8.0 초  settled_with_residual 3/3 · 소요 1790~3301ms           최악  21~30틱
```

3.0초 사망의 원인은 **최대 소요 3301ms > 3000ms**. 값 자체가 경계였다.
`settle_timeout < 1.0` 은 구조적으로 불가능하다 — 소스가 "1초간 not moving" 을 요구한다
(`robot_controller.py:106-143`). 0.5초는 그 분기에 도달할 수 없어 항상 timeout 이다.

## 2. 포화가 아니라 정상편차다 🟢

`torque_limit_raw = 1000` (최대), 6/6 서보. **이건 천장이 안 낮춰졌다는 뜻일 뿐이다.**
실제 포화 여부는 `present_load_raw` 로만 갈린다 — 정지 유지 중 실측:

```
서보2 load 189→65 · 잔차 12틱      서보3 load 0 · 잔차 1틱      서보4 load 64 · 잔차 7틱
```

최대 **189/1000 = 19%**. 여유 81%. → 목표를 잔차만큼 더 밀면 상쇄된다는 예측이 섰고,
재명령 실측으로 확인됐다(부하 208~240 = 24%).

## 3. tolerance 는 틱이 아니라 z 로 정해야 한다 ⚠️

재명령 런의 c4 가 `arrived` 로 빠져 재명령을 건너뛰었다. 잔차 13틱 ≤ tolerance 15.
**그런데 z 로는 −9.3mm 였다.**

```
13틱 = 9.3mm   (실측 1점)
```

→ `--settle-tolerance` **5** 로 내린다(약 3.6mm). 게이트 변경이 아니라 z 목표에서 역산한 제어 파라미터다.

## 4. 재명령 패치 설계

`[JT-PATCH settle-recommand]` · `patch_runtime_jt_settle.py` · 자체검사 11/11 · 멱등

```
settle 종료 후 잔차 worst > tolerance 이면
    새 목표 = 현재 목표 + 잔차 * gain   (관절 한계 클램프)
    전송 → not-moving 대기 → 재측정
    최대 --settle-retries 회 (기본 0 = 현행 동작 그대로)
기록: 회차 · 보정 틱 · 재측정 잔차 · present_load_raw
```

기본값 0 이라 패치 전후 비교가 흔들리지 않는다.

## 0. 답한 질문

**"잡고 드는건 왜 안한거지"**

→ **들기 전에 파지 자체에 도달하지 못한다.** 🟢
정책은 내려가는 것은 배웠지만 **어디서 멈출지를 모른다.** 물체를 지나쳐 계속 하강한다.

지난주 성공한 런(57사이클 · latch 55/57 · 파지 유지)은 물체가 그리퍼 바로 앞(≈5cm)에 있어
하강 도중 물체 높이에서 닫힌 경우로 보인다 🟡 — n=1 이라 단정하지 않는다.

## 4. 서보 상태 계측 🟢

### 런 1 직후

```
servo 1 shoulder_pan   33°C  status_raw=0x00  volt=125
servo 2 shoulder_lift  43°C  status_raw=0x00  volt=124   ← 유일하게 높다
servo 3 elbow_flex     34°C  status_raw=0x00  volt=124
servo 4 wrist_flex     35°C  status_raw=0x00  volt=124
servo 5 wrist_roll     33°C  status_raw=0x00  volt=125
servo 6 gripper        34°C  status_raw=0x00  volt=124
응답 6 / 전체 6 · torque_enabled 전부 False
```

버스는 살아 있다. 체크섬 오류는 **일시적**이었다.

### 10분 뒤

```
servo 2  41°C  (43 → 41, 하강 추세) · 나머지 33~35°C · status_raw 전부 0x00
```

### 런 2 직후 (토크 해제 뒤)

```
전 서보 status_raw=0x00 · torque_enabled False · volt 124~125 · load 0 · cur 0
servo 2  41°C
servo 6 gripper  tick=124  goal=1112     ← 988틱 괴리
```

**플래그는 토크 해제로 해제됐다.**

### 미검증 — `0x20` 의 의미

`servo_control.py` 는 STATUS 레지스터를 `status_raw` 로 **그대로 넘길 뿐 비트를 해석하지 않는다.**
소스 전수 grep 으로 확인했다 — 에러 비트 정의가 없다.

→ **ST3215 데이터시트 대조 전까지 "과부하"라고 적지 않는다. 미검증.**

### 미검증 — 그리퍼 988틱 괴리

`GRIPPER_OPEN_TICK 130 · GRIPPER_CLOSED_TICK 1763 · OPEN_WIDTH_M 0.09` 🟢
→ tick 124 = **완전 개방**(OPEN 한계보다 더 열림), goal 1112 ≈ **36mm 개구**.

닫으라는 명령 상태에서 물리적으로 활짝 열려 있었다. 두 해석이 갈리지 않는다:

```
(a) 토크 해제 시 튕겨 열림      → 정상
(b) 애초에 명령을 못 따라감      → 문제
```

→ 다음 런에서 `maximum_live_gripper_lag_ticks` 를 **사이클별로** 찍으면 갈린다. 미측정.

## 5. 정정

### 정정-3 · "로봇 파지 z 48mm" 를 가설 근거로 썼다

세션 중 *"시연 파지 z 108~264mm vs 로봇 파지 z 48mm — 높이 분포가 어긋난다"* 라고 말했다.
48mm 는 **물체 배치가 다른 이전 런의 값**이다.

물체를 5cm 띄운 현재 배치에서 실측 z 는 **85.5 ~ 127.6mm** 로 이미 시연 분포 안이다.

→ **높이 불일치 가설(②)은 이 배치에서 근거가 없다. 기각하지는 않되 근거를 잃었다.**

### 정정-4 · 근거 없는 온도 게이트

재시도 조건으로 "servo 2 가 38°C 이하" 를 박았다. **ST3215 의 한계 온도를 확인하지 않고 찍은 숫자다.**
게이트를 낮춘 것이 아니라 애초에 잘못된 게이트라 폐기했다.

대신 계측된 것으로 판단했다:
- `status_raw = 0x00` — **서보 자신의 플래그가 안 섰다.** 추정이 아니라 서보의 판정
- 온도 하강 추세 (43 → 41)
- 전압 전 서보 균일

| **정책 `target_table_mm` vs 실제 물체 위치의 차이** | 상수 편향이면 hand-eye, 사이클마다 흔들리면 관측 문제. 지금은 둘을 가를 데이터가 없다 |

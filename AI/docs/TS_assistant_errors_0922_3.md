# TS — 2026-09-22 어시스턴트 오류 (3차, 실물 세션 후반)

작성자: 김준태(트랙 B) 기록 · 오류 주체는 어시스턴트

> 오늘 세 번째 묶음. **7건 중 4건이 같은 모양이다 — "데이터 없음"과 "정상"이
> 같은 출력으로 나오는 것을 증거로 썼다.** 프로젝트 지침 첫 줄에 적혀 있는 결함이다.

## A. 없음 ≠ 괜찮음 (4건)

**A-1. `torque_limit_raw = 1000` 을 보고 "물리 한계 확정"이라고 했다**
레지스터 최대값은 **천장이 안 낮춰졌다**는 뜻이지 **서보가 그 천장에 닿았다**는 뜻이 아니다.
실제 포화는 `present_load_raw` 로만 갈린다. 실측 결과 최대 19% 로 **포화가 아니었고**,
그 위에 세운 "소프트웨어로 못 고친다"는 결론 전체가 틀렸다.
→ 가용성 확인 ≠ 기능 확인. 지침에 이미 있던 항목을 그대로 반복했다.

**A-2. 그리퍼 개구 33.3mm 5사이클 고정을 "물체를 물었다"의 증거로 썼다**
**막혀서 멈춘 것**과 **명령대로 도달해서 멈춘 것**이 같은 숫자로 나온다.
사용자가 "못 물었다, 도착 전에 닫았다"고 직접 정정했다. 실제로는 정책이 학습한
폐쇄 폭에 도달한 것이었다.

**A-3. `present_load_raw = 0` 을 "접촉 없음"의 증거로 썼다 — 두 번**
① 토크가 OFF 면 물든 안 물든 0 이다. 토크 상태를 안 보고 읽었다.
② 내가 출력한 부하는 **재명령 로그**에서만 나온다. 재명령이 0회인 사이클은
   부하가 **아예 안 찍힌다**. 정작 그리퍼가 닫힌 구간의 부하를 한 번도 못 봤다.

**A-4. c10 이후 처짐 재발을 "물체 하중 때문"이라고 했다**
A-2 가 틀렸으므로 물체가 없었고 이 설명도 죽는다. 실제 원인은 자세 의존(모멘트).
결론(재명령 회수를 올린다)은 같았지만 **근거가 틀린 채로 맞았다.**

## B. 확인 전에 결론·요청을 냈다 (3건)

**B-1. 물체를 캔으로 가정했다**
시뮬 스펙(YCB 토마토수프캔 ⌀67.8mm)을 실물 런에 그대로 전이했다.
실제는 **41mm 구운감자**. 폭 계산과 "캔보다 좁다/넓다" 판정 전부 무효.
사용자 지적: *"갑자기 캔이 어디서 나온 거냐"*.

**B-2. `execSliceAppliesTo` 를 EC2 쪽에서 고쳐달라고 요청한 뒤 철회했다**
근거가 **우리 manifest 안에** 있었다(`convertedDim 7` / `convertedLayout` /
행 단위 1:1). `json.tool` 한 번이면 요청 자체가 불필요했다.
조건부 수용안을 같이 달아둔 덕에 실제 라운드트립은 없었다.

**B-3. BE 폴백의 `"raw"` 를 BE 버그로 지적했다**
사용자 지적: *"저거 raw로 우리가 고쳐달라 했던 거잖아"*. git 이력 확인 결과
해당 필드는 **2026-09-18 `673100d`** 에 먼저 들어갔다 — 우리 요청보다 나흘 앞선다.
어느 쪽이든 **확인 없이 상대 트랙에 책임을 돌렸다.**

## C. 도구 사용 (1건, 반복)

**C-1. 긴 heredoc 을 터미널에 붙여넣게 해서 세 번 깨졌다**
`EOF` 줄이 앞줄과 엉켜 스크립트가 잘렸다. 사용자 저장 지침에 *"명령은 그대로
복붙해서 돌아가야 한다"* 가 있고, 프로젝트 지침에도 *"터미널·붙여넣기 문제는
대개 명령을 길게 낸 어시스턴트 탓"* 이라고 적혀 있다.
→ **20줄 넘으면 파일로 전달한다.** 이번 세션에서 두 번 어겼다.

## 재발 방지 — 계측기 규칙에 추가할 것

1. **상태값을 증거로 쓰기 전에 "이 값이 두 경우에 같게 나오지 않는가"를 먼저 묻는다.**
   레지스터 최대값 · 목표 도달 · 토크 OFF 의 0 — 전부 이 모양이었다
2. **로그에 없는 구간을 "그랬다/아니었다"로 말하지 않는다.** 모수를 먼저 센다
3. **실물 물체·배치는 사용자에게 확인한다. 시뮬 스펙을 전이하지 않는다**
4. **상대 트랙에 수정 요청을 내기 전에 우리 파일부터 연다**

## 3. 확정 ① — 조기 폐쇄 🟢

지표: **닫기 시작 프레임 / 파지 프레임** (0 = 처음부터 닫음, 1 = 마지막에 닫음)
"닫기 시작" = 개구가 전체 범위의 10% 만큼 줄어든 첫 프레임.

```
시연 94/94 · 미판정 0
  min 0.690 | q1 0.866 | 중앙 0.899 | q3 0.922 | max 0.965

실물  성공 5cm  0.256  → 시연 분포 하위 0.0%
      실패 10cm 0.426  → 시연 분포 하위 0.0%
```

시연은 **접근의 90%를 활짝 연 채로 가다가 마지막 10%에서 닫는다.**

## 4. 확정 ② — 접근 방향 불일치 🟢

시작 → 파지 순변위의 축별 분해 (94/94 · 미판정 0):

```
축별 |변위| 비중 (편별 계산 후 중앙)
  x  54.4%   y  83.9%   z  1.1%  (q1 0.6 · q3 2.2)
지배축이 z 인 편   0 / 94
z 순변위 중앙 0.8mm (q1 −0.9 · q3 2.7)
```

**시연은 높이를 유지한 채 수평으로만 접근한다.**

실물:

```
far  (실패)  순변위 (28.9, 4.9, −50.3) mm  → z 비중 86%
lift3(성공)  순변위 (13.1, −19.8, −13.4) mm → z 비중 49%
```

**두 런 다 시연 분포 밖.** 로봇은 시연에 없는 동작을 한다. 사용자 관찰과 일치 —
*"근처가서 좀더 전진해야하는데 안하고 내려가면서 그리퍼를 점점 닫더라"*.

⚠️ **한계**: 시연 z 가 수직축이라는 것은 "변화가 거의 없다"는 간접 근거다.
SLAM 지도의 중력 정렬 여부로 확정해야 한다. **미검증.**

## 5. 유력 — 그리퍼 폭 관측 척도 불일치 🟡

```
            시작 개구                      파지 개구
시연        70.7mm (q1 69.5 · q3 72.8)     45.8mm (q1 43.4 · q3 47.1)
실물        79.0mm                          36.8 / 37.6mm
```

**양쪽 끝 다 시연 사분위 밖이다.** 로봇은 시연보다 더 열고 시작해 더 꽉 닫는다.
첫 관측부터 분포 밖이면 닫는 방향 액션이 처음부터 나온다.

정책 출력 그리퍼 개구에 **톱니**가 보인다:

```
… 42 40 39 37 | 42 40 39 37 | 41 40 39 38 …
```

매 청크가 다시 열었다 닫는데 `--gripper-close-offset-ticks 25` latch 가 되돌림을 막아
**한 방향으로만 래칫된다.**

**로봇 필요한 검증**: 시작 그리퍼를 시연 중앙(70mm)에 맞춰 놓고 동일 조건 재실행.
닫기 비율이 0.69 이상으로 오르면 척도 불일치 확정.

## 6. 미검증 — 프레임 회전. 스윕이 실패했다

액션 벡터 → 테이블 프레임 변위의 상수 회전을 Kabsch 로 적합했다 (자체검증 3/3).

```
             전역 회전각   배율    잔차RMS   B 크기 중앙
lift3 H1       76.3°     0.516    5.40mm      4.54mm
lift3 H2       92.9°     0.467    5.37mm      4.54mm
far   H1      102.5°     0.315    5.79mm      3.55mm
far   H2      111.3°     0.332    5.84mm      3.55mm
```

**잔차가 신호 크기와 같다. 설명력이 없다.**

원인은 계측 설계 한계다 — 액션 각 행에 회전(rot6d)이 들어 있어 스텝마다 TCP 자세가 돈다.
사이클당 상수 회전 가정이 성립하지 않는다.

→ **회전각 76~111°, 배율 0.32~0.52 는 인용 금지.** 아무것도 확정하지 않는다.

**가르는 방법**: 실행부 소스(`policy_runtime.py` · `motion_planner.py`)의 액션→테이블
변환을 그대로 구현해 정답 아는 행으로 검산한다. 잔차가 0 근처로 떨어져야 한다.
로봇 불필요.

가장 유력한 기계적 원인 🟡: **핸들 → 손목 장착 변경.** `camera_tcp` 는 폰이 UMI 핸들에
달린 조건에서 검증됐다. `MEASURE_jetson_live_0922.md` §5 에 이미 "미측정"으로 적혀 있던 항목이다.

## B. 받은 자료를 준비물 목록과 대조하지 않았다 — 1건

tar 를 푼 직후 **궤적 개수만 세고 넘어갔다.**
내가 노트북 셀 4 안내문에 *"받을 것: `camera_trajectory.csv` · `trajectory_validation.json` ·
`gripper_width.csv` · `telemetry.json`"* 라고 **직접 써놓고** 그 목록과 대조하지 않았다.

결과: 게이트가 96/96 을 떨어뜨린 뒤에야 `gripper_width.csv` 부재를 발견했다. **30분 손해.**

→ **추가 규칙: 산출물을 받으면 압축 해제 직후 준비물 목록과 대조한다. 개수만 세지 않는다.**

## C. 게이트 수정과 자체검증을 따로 고쳤다 — 1건

`SOFT_NAMES` 에 3항목을 옮겨놓고 **자체검증 기대값을 같이 안 고쳤다.**

```
FAIL  2 검사 항목 수 (필수 10 · 권고 2)   필수 7 · 권고 5
FAIL  5 검출률 미달 -> FAIL (판별행)
자체검증 9/11 → !! 수치를 내지 않는다
```

**계측기가 제대로 막았다.** 자체검증이 깨진 채로 수치를 냈으면 그게 더 나빴다.

→ **추가 규칙: 게이트의 임계·등급을 바꾸면 자체검증 기대값을 같은 커밋에서 바꾼다.**
   판별행의 **의미**도 함께 바꾼다 — "검출률 미달 → FAIL" 은 "검출률 0.5 → 경고, 판정 PASS
   (정답 아는 행)" 으로 뒤집혀야 한다.

## D. 비용을 재지 않고 결론을 먼저 말했다 — 1건

`camera_tcp` 가 미검증이라는 것만 보고 **"물리검증판을 받아 zarr 재빌드 → 재학습 2.6시간"**
이라고 말했다. 사용자가 *"어젠 그럴 일 없다며"* 로 지적했다.

실제로는:
- 두 판의 차이를 재지도 않았다 (재보니 축 90도 · D 행렬)
- 상대 궤적이라 conjugation 보정으로 재학습 없이 된다 — **내가 전날 직접 확정한 사실**
- 젯슨 추론이 `camera_tcp` 를 쓰는지도 안 봤다 (`metadata.json` 에 없다)

→ **추가 규칙: 재작업 비용을 말하기 전에 차이의 크기부터 잰다.**
   "미검증" 은 "얼마나 틀렸는지 모른다"는 뜻이지 "많이 틀렸다"가 아니다.

## F. 로그에 거짓 종료코드를 찍었다 — 1건

`day.sh` 에서:

```bash
$PG make_jetson_package.py ... > $O/jetson.log 2>&1
echo "[$(stamp)] $N 젯슨 종료코드 $?"
```

`$(stamp)` 가 **command substitution 이라 `$?` 를 덮어쓴다.** 항상 0 이 찍혔다.
실제 판정은 FAIL 이었다.

**"없음과 괜찮음이 같은 출력으로 나오는 검사는 검사가 아니다"의 변종**이다 —
실패와 성공이 같은 출력으로 나왔다.

→ **추가 규칙: `$?` 는 다음 명령 이전에 변수로 받는다. `rc=$?` 를 먼저 쓴다.**

## G. 계측기 이름 충돌을 예상 못 했다 — 1건

→ 계측기 개선 여지: 이름이 겹치면 부모 디렉터리까지 포함해 구분하고, 그 사실을 출력한다.

## I. 저녁 실물 런 구간 — 5건

### I1. 클래스 이름을 추측해서 **거짓 판정을 출력했다** ⚠️ 최악

서보 진단 스크립트에서 `servo_control.ServoBus` 를 가정했다. 실제는 `ST3215Bus`.
게다가 방어적으로 쓴다고 이렇게 썼다:

```python
bus = servo_control.ServoBus() if hasattr(servo_control, "ServoBus") else None
```

결과:

```
servo 1: FAIL AttributeError 'NoneType' object has no attribute 'read_diagnostics'
...
응답 0 / 전체 6
```

**"응답 0 / 전체 6" 은 버스 상태가 아니라 내 버그였다.**
그 순간 판단해야 했던 것은 "서보 6개가 다 죽었는가"였고, 출력은 정확히 그렇게 읽힌다.

이것이 프로젝트가 반복해서 경고한 바로 그 모양이다 —
**"없음"(버스 고장)과 "내가 못 물어봄"(bus=None)이 같은 출력으로 나왔다.**
모수를 병기했는데도 막지 못했다. 모수는 분모가 맞을 때만 의미가 있다.

→ **추가 규칙: 계측기 앞에 "계측 가능 상태였는가"를 먼저 찍는다.**
   `bus is None` 이면 0/6 을 내지 말고 `계측 불가` 로 죽어야 한다.
   `hasattr ... else None` 같은 조용한 폴백을 계측기에 넣지 않는다.

### I2. `torque.py off` 를 `--help` 대조 없이 냈다

```
torque.py: error: `off` needs --ids or --all (the arm goes limp; hold it first)
종료코드 2
```

A3·A4 와 **같은 유형의 세 번째 재발.** 규칙이 이미 있는데 또 틀렸다.
게다가 이건 **모터 보호 명령**이라 실패 비용이 다른 것들보다 크다.

### I3. 근거 없는 게이트를 박았다 — "servo 2 가 38°C 이하면 진행"

ST3215 의 한계 온도를 확인하지 않고 숫자를 찍었다. 41°C 가 나오자 스스로 폐기했다.

폐기 자체는 맞지만, **게이트는 결과를 보기 전에 박는 것**이라 근거 없이 박으면
"게이트를 낮췄다"와 구분이 안 된다. 다행히 판단 근거를 계측된 것
(`status_raw=0x00` = 서보 자신의 판정, 온도 하강 추세)으로 갈아끼웠다.

→ **추가 규칙: 게이트 숫자에 출처를 병기한다. 출처가 없으면 게이트가 아니라 감이다.**

### I4. 배치가 다른 런의 값을 가설 근거로 인용했다

*"시연 파지 z 108~264mm vs 로봇 파지 z 48mm"* 라고 말했다.
48mm 는 **물체 배치가 달랐던 이전 런**의 값이다. 현재 배치 실측은 85.5~127.6mm 로
이미 시연 분포 안이다.

프로젝트 절대원칙 3(**모든 수치에 측정 조건 병기**) 위반이다.
조건을 안 적으면 다른 실행끼리 같은 키로 조회된다 — 계측기 규칙에 그대로 적혀 있다.

### I5. 명령 블록 접두어 오타 — `# [젯셋]`

명령 자체는 돌아갔다. 다만 접두어는 **로컬/서버/젯슨을 섞지 않기 위한 장치**라
오타가 나면 장치가 작동하지 않는다.

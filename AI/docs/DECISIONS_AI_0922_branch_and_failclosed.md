## D-AI-52 · 학습 데이터 설정으로 `episode_start_trim_s: 0.0` 을 명시한다

### 결정

### 근거 ① — 기본값이 파지 순간을 데이터에서 지운다 🟢

같은 10편, config 만 바꾼 대조:

| | 기본값 trim 3.0 | **trim 0.0** |
|---|---|---|
| 프레임 합계 | 1467 | **2367** |
| 편 길이 중앙 | 156 | **246** |
| **파지 닫힘 채점** | **0 / 10편** | **10 / 10편** |
| 파지 개구 중앙 | 산출 불가 | **40.3 mm** |
| 개구 p10–p90 폭 | 산출 불가 | **0.78 mm** |
| 게이트 미판정 | **1** | **0** |

차이가 설정값과 정확히 일치한다:

```
2367 − 1467 = 900 프레임 = 90 × 10편
90 프레임 / 30 Hz = 3.00 초
```

**닫힘이 0편이어도 빌드는 `status: pass` 로 끝나고 학습도 정상으로 돈다.**
파지를 한 번도 본 적 없는 정책이 아무 오류 없이 만들어진다.
우리 감사기(`audit_umi_zarr.py`, 자체검증 12/12)가 `파지 닫힘 0/10` · `미판정 1` 로 잡았다.

개구 폭 0.78mm 는 참조 배치보다 좁다 — 현석 v4 1.55mm · s22_pick_v3 1.4mm.

### 근거 ② — "official" 은 운영값이 아니라 빌더 기본값이다 🟢

갈래 이름 때문에 오해가 생겼다. B/D/F 의 `trim 3.0` 은 **빌더 기본값**이고,
현석 배치는 전부 `episode_start_trim_s: 0.0` 이었다 (v4 · s22_pick_v3 · 20260921 report).

→ 정확한 표현은 **"공식 vs 우리 튜닝" 이 아니라 "빌더 기본값 vs 명시 설정"** 이다.
갈래 이름 `ours` / `official` 은 이후 문서에서 `trim0` / `trim3` 으로 부른다.

## D-AI-53 · 실행부에 fail-closed 청크 검사를 켠다

**작성자** 김준태(트랙 B) · **상태** 제안 🟡 (현석 소유 코드 수정 필요)

### 배경

도경의 v10 인수인계 문서 §9 — *"N개만 실행하더라도 8개 전체를 먼저 검사하고,
후속 waypoint 하나라도 실패하면 전체 chunk 를 거부하는 fail-closed 경계를 사용한다."*

우리 실행부에는 **틀이 이미 있는데 죽어 있다:**

```python
# motion_planner.py:94

# cli.py:327
if attempt < args.max_resamples:   # 그래서 재샘플이 한 번도 발동하지 않는다
```

`ik_ok` · `limits_ok` · `workspace_ok` · `path_min_z_mm` · `minimum_joint_margin_ticks` 가
전부 **계산은 되는데 판정에 쓰이지 않는다.** 오늘 10개 런 전부 `attempt 0`.

### 제안

`safe` 를 위 검사들의 논리곱으로 바꾼다. 청크 4개 중 하나라도 불합격이면 전체를 거부하고
`--max-resamples` 범위에서 다시 샘플링한다.

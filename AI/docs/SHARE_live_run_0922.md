## 1. 우리 파이프라인 정책이 실물에서 파지·들어올리기를 완주했다 🟢

```
조건  물체 5cm 이격 · 15사이클 · gripper_close_offset 25
모델  pv_E = 자체 수집 실 시연 94편으로 학습한 ours 갈래
      (현석 공식 ckpt 아님. 데이터·학습·젯슨 패키지 전 경로가 우리 것)
결과  접근 → 파지 → z +21.4mm 상승. 육안 확인 + 로그 일치
```

수집 → zarr → 학습 → 젯슨 패키지 → 실물 구동까지 **전 경로가 한 번 끝까지 통했다.**

⚠️ **n=1.** "된다"는 확인됐고 "얼마나 자주 되는가"는 아직 모른다.

## 2. 결함 2개 — 오늘 실물 런 7개 전부에서 재현 🟢

### (a) 팔이 명령보다 낮게 관측된다 → 누적 하강

```
7/7 런에서 z 처짐 중앙이 음수 (−2.80 ~ −10.29 mm)
7/7 런에서 종료 z 가 시작보다 낮다
```

액션이 상대 좌표라 낮아진 지점이 다음 명령의 기준이 된다. 편차가 보정되지 않고 쌓여
**팔이 테이블 쪽으로 걸어 내려간다.** 정책 명령 자체는 매 사이클 위쪽이었다.

원인: 러너 인자 `--settle-timeout` 기본값이 0 이고, 도움말에 `"0 skips final-target waiting"`.
모든 사이클 `settle_status: skipped` — 목표 도달을 확인하지 않고 다음 관측으로 넘어간다.

### (b) 그리퍼를 시연보다 훨씬 이르게 닫는다

```
닫기 시작 시점 / 파지 시점
  시연 94편   0.690 ~ 0.965 (중앙 0.899)   ← 접근의 90% 를 열고 가다 마지막에 닫음
  실물 7런    0.140 ~ 0.465                ← 전부 시연 최소값 밖

시작 개구  실물 10/10 런 79.0mm · 시연 중앙 70.7mm (q3 72.8)
```

접근이 끝나기 전에 닫혀서 공중/바닥에서 닫는다.

## 5. HW 확인 요청 (김현석)

```
shoulder_lift (servo 2) 가 오늘 두 차례 구동을 중단시켰다
  12:25  invalid response checksum
  12:35  servo 2 error: 0x20
온도      43°C (나머지 서보 33~35°C) · 전압 124~125 전 서보 균일
현재      status_raw 0x00 · 토크 해제로 플래그 해제됨
```

`0x20` 비트의 의미는 `servo_control.py` 가 STATUS 레지스터를 해석하지 않아 **미확정**이다.
ST3215 데이터시트 대조가 필요하다.

## 0. 결론

```
--settle-timeout 기본값 0  ("0 skips final-target waiting")
  → 모든 사이클 settle_status: skipped · 정착 대기 70ms
  → 엘보가 명령보다 +17틱 뒤처진 채로 다음 관측 (far 런 0/14 만 음수 = 항상 같은 방향)
  → FK: 엘보 +17틱 = TCP z −7.28mm · lift +17틱 = −8.12mm
  → 관측 z 가 명령보다 낮다 (오늘 7개 런 전부 음수)
  → 액션이 상대라 낮아진 지점이 다음 청크의 기준이 된다 → 누적
  → 팔이 테이블로 걸어 내려간다
```

**정책은 매 사이클 위로 명령하고 있었다.** 내려간 것은 실행 루프다.

## 1. 정정 — 앞 문서·세션 중 발언 3건


로봇 접근축은 **거의 수평이다.** 시연과 7~14° 차이일 뿐이다.
**순변위 방향에서 자세를 역산하면 안 된다** — 액션의 TCP x·y 성분이 섞여 들어온다.

**정책의 명령은 상승이다.**

### 정정-7 · 프레임 회전 가설 — 기각

## 2. 실행부 변환 — 소스로 확정 🟢

```python
# robot_controller.py:33
"pose": kinematics.fk(q)                       # SO-101 TCP (관절각 FK)

# motion_planner.py:67-69
for action_index, row in enumerate(action[1:5], start=1):   # 실행은 1~4행
    target = state["pose"] @ pose10d_to_mat(row[:9])        # state.pose 는 청크 내 고정
    target_table = kinematics.table_from_base(target[:3, 3])
```

- 실행되는 행은 `action[1:5]` — **0행이 아니다**
- 각 행은 증분이 아니라 **현재 자세 기준 절대 포즈**. 청크 내 `state["pose"]` 는 갱신되지 않는다
- 따라서 TCP 프레임에서의 청크 순변위 = `action[4][:3]`

### `camera_tcp` 는 변환에 쓰이지 않는다 🟢

```python
# calibration.py:34-39 — load_camera_tcp_config 의 반환
{"path", "sha256", "status", "image_orientation_contract"}     # 행렬 없음
```

해시 대조와 검증에만 쓴다. 실물 프레임은 `kinematics.fk(q)` 가 전부다.
(정정-7 로 이것이 실패 원인은 아님이 확인됐지만, **규약으로 기록해 둔다.**)

### 재샘플은 "여러 개 중 고르기"가 아니다 🟢

```python
# cli.py:327  if attempt < args.max_resamples:   안전 게이트 실패 시 재질의
# motion_planner.py:94  safe = True              상수
```

`safe` 가 상수 True 라 `full_chunk_safe` 는 항상 참이고 **재샘플이 한 번도 걸리지 않는다.**
오늘 10개 런 전부 `attempt 0`. 정책은 사이클당 **샘플 1개**를 내고 그대로 실행한다.

## 3. 누적 하강의 계측 🟢

사이클별 (관측 TCP z) / (명령 최종 z) / (다음 관측 z):

```
far (실패)   명령 상승 중앙 +2.1 mm · 실제 변화 중앙 −7.7 mm · 미달 중앙 −9.2 mm
             명령보다 낮게 끝난 사이클 12/14
lift3(성공)  명령 상승 중앙 +3.1 mm · 실제 변화 중앙 +0.3 mm · 미달 중앙 −4.1 mm
             명령보다 낮게 끝난 사이클 8/14
```

관절 틱으로 분해 (다음 관측틱 − 명령 최종틱, 음수 = 덜 감):

```
far   servo 3 elbow  중앙 +17.0 · q1 +6.2 · q3 +26.2 · 음수 0/14   ← 항상 같은 방향
      servo 2 lift   중앙  +0.0 · 음수 7/14
lift3 servo 2 lift   중앙  +8.0 · 음수 6/14
```

FK 감도 (기준 자세 TCP z 93.46mm, far 런 c7):

```
pan   +17틱 → Δz  +0.00 mm
lift  +17틱 → Δz  −8.12 mm
elbow +17틱 → Δz  −7.28 mm
wflex +17틱 → Δz  −5.69 mm
wroll +17틱 → Δz  +0.00 mm
1틱 = 0.0879°
```

far 런에서 엘보 관측틱은 3097 → 2837 로 **감소** 중이었다. 명령보다 +17틱 높다는 것은
**하강 명령을 덜 따라갔다**는 뜻이고, 그 자세는 명령 자세보다 z 가 7.3mm 낮다.

### 왜 누적되는가

액션이 **상대**다. 매 사이클 정책은 *관측된* 자세를 기준으로 다음 청크를 낸다.
관측 자세가 명령보다 9mm 낮으면 그 낮은 지점이 새 기준이 된다. 편차가 보정되지 않고 쌓인다.

## 5. 한계

- **배치 조건별로는 여전히 n=1.** 5cm 성공 1회, 10cm 실패 1회다.
  n=7 은 "두 결함이 모든 런에 있다"를 말할 뿐 "거리별 성공률"을 말하지 않는다
- `--settle-timeout` 을 켜면 사이클 시간이 늘어난다. 관측 간격 게이트
  (`observation_interval_target_ms`)와 충돌하는지 미확인
- 엘보 지연의 원인(속도·가속 설정 / 부하 / PID)은 미분리.
  `--speed 100 --acceleration 30` 이 적절한지 측정한 적 없다
- servo 2 가 43°C 까지 올랐던 것과의 관계 미확인
- 닫기비는 `predicted_gripper_mm` 기반이다. 물리 개구가 아니라 정책 예측값이다

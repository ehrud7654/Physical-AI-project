## 확인된 것
- **servo 2 통신 불량 원인은 모터가 아니라 1↔2 케이블/커넥터** 🟢 — 모터 2개 연속 같은 자리 실패, 케이블 맞바꿈 후 0/558. 불량 케이블이 4↔5 로 갔을 수 있음(미확정: 4~6번 오류 재발 시 확정)
- **정책은 그리퍼 기준 상대 동작이라 시작 화면만 맞으면 된다** 🟢 — align.py dy/rot 0 근처에서 접근·운반 정상화
  - 보정 계수: 손목(4) **0.30 px/틱** (−틱 = 위로), 손목회전(5) **−0.094 °/틱** 🟢
- **정책은 놓기를 약하게 배웠다** 🟡 — 상자 위 폭 신호 r20 최대 55.3, r21 최대 48.6, r23 c35–36 ≈ 46~46.5mm. 쥘 때 약 41~43mm 대비 +3~14mm
- **r23 에서 감자가 빠진 기전** 🟡 — 풀림 뒤 명령틱이 1185(squeeze) → 938~991(정책 폭 ≈ 43~45mm)로 돌아가 쥐는 힘이 빠졌다. 80mm 로 벌린 것은 아니다
- **정책은 상자 안으로 내려가서 놓으려 한다** 🟡 (r23 정책z 205→144)
- 새 모터로 z 기준값이 바뀌어 **절대 z 값은 어제와 비교 불가**

1. r23 을 "위치 규칙으로 놓았다" 고 말함 — 패치 미적용(grep 0). 확인 없이 단정
2. release 기준 250틱을 데이터 없이 정함 → r20 0.7mm 차로 놓기 실패
3. floor ramp 를 관측 z 기준(obs+20)으로 설계 → 팔이 처지면 바닥도 같이 내려감(r23 c22 이후 220→157). 결과적으로 하강을 허용했지만 의도와 다름
4. "전류 클 때만 깨진다" 가설 → 정지 토크OFF 12.5% 실패로 기각
5. "3.4% 면 재시도 8회로 충분" → 실패가 몰려서 옴(8연속). 독립 가정 틀림
6. 새 모터 영점 차이를 처음에 "수평 재저장" 눈대중으로 해결하려 함 → 화면 기준 계측(align.py)이 답
7. 명령에 여러 줄 python -c 사용 (한 줄 규칙 위반, 동작은 함)
8. 젯슨 로그를 직접 못 읽는데 로그 회수 경로를 처음부터 깔지 않아 "로그 봐바" 왕복이 반복됨

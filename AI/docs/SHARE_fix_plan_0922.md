## 중요한 구분 셋

**① 2번은 해결책이 아직 없다.**
조기 폐쇄의 원인이 확정되지 않았다. 3번이 1순위 후보지만 **추정이다.**
3번 고치고 닫기비가 안 오르면 다른 원인이다.

**② 1·3 은 재학습·코드수정 없이 된다.**
인자 하나와 물리 세팅 하나다. **로봇만 있으면 끝난다.**

**③ 4·6·8 은 현석 코드다.**
트랙 간 공유 코드라 고치면 그쪽 런 동작이 바뀐다 — 영향 명시하고 합의해야 한다.
특히 **4번은 현석 런에서도 재샘플이 걸리기 시작한다.** 지금은 기본 꺼짐(`--fail-closed` 미지정 시
원본과 동일)으로 만들어 뒀으니, 합의 전까지는 우리 런에서만 켠다.

## 실행 순서 — 한 번에 하나씩

```
런1  settle 만                    → z 처짐만 판정
런2  그리퍼 틱 480 만              → 닫기비만 판정
런3  둘 다                        → 10cm 파지·리프트
런4  + --fail-closed              → 거부율·완주 여부
런5  런3 반복 (5cm·10cm 각 3회)    → 성공률
```

배치는 런 1~4 내내 **중앙 10cm** 고정. 한 번에 여러 개 켜면 어느 게 들었는지 못 가른다.
상세 명령·판정 기준은 `RUNBOOK_real_0922_fixes.md`.

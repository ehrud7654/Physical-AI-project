## ⚠️ 교락 — 이 차이를 게이트 효과로 읽으면 안 된다

**두 변수가 동시에 바뀌었다.**

```
plan         70편(현석 선별)      vs  67편(우리 게이트)
camera_tcp   물리검증 4e16c0a2   vs  미검증 00955e02
```

`camera_tcp` 는 **카메라→TCP 변환**이라 pose 의 회전 성분에 직접 들어간다.
회전 폭 0.749 → 0.519 (−31%) 가 **게이트 때문인지 hand-eye 때문인지 구분할 수 없다.**

노트북 `CAM_TCP` 가 서버 기본값(미검증판)을 가리킨 채로 빌드됐다. 물리검증판은
현석 머신에만 있고 서버·로컬 어디에도 없다 (전수 탐색 확인).

**조치** — 물리검증판을 받아 같은 plan 으로 재빌드한다. 그때 비로소 plan 단독 효과가
분리된다. 지금 빌드는 버리지 않는다: 재빌드본과의 짝이 **hand-eye 효과**를 분리해준다.
